# 受付〜受注登録 基本設計書

Oct 17, 2026 · @よしみ

受注システム本体（`docs/basic-design.md`）に、届いた注文を受け付けてから受注登録するまでの流れを追加する。本書は「何を作るか」を定義し、画面は `docs/intake/screen-design.md`、テーブルは `docs/intake/table-design.md` に書く。受注登録画面そのもの（明細の入力）は本体の設計書に従う。

## 背景と目的

### 現在の業務フロー（本社シャーリング部）

1. メールが届くと、メールの表紙を印刷する
2. 添付ファイルを共有フォルダの「受付待ち」に当たる場所へ保存する
3. Excel でメール番号を割り振り、DXF のファイル名にメール番号を付けて、顧客ごとのフォルダへ移動する
4. メールの表紙にメール番号を手書きする
5. 顧客フォルダから DXF を図面ソフトで開き、**先寸** と **アイトレ** に分けて印刷する（データは分けず、見やすく図面を移動して上書き保存するだけ）
6. メールの表紙をもう 1 枚印刷し、「表紙＋先寸」「表紙＋アイトレ」の 2 セットにする
7. 先寸は **起票待ちのカゴ** へ、アイトレは **CAD の部品作成待ちのカゴ** へ入れる
8. アイトレは CAD で部品を作成し、CSV を事務へ渡す → 起票
9. FAX の注文は紙で届き、起票後にコピーへ手書きで転記・スキャン・ファイル名の手入力が発生している

### 課題

- 番号の手書き・ファイル名の手入力が多く、紐付けミスが起きる
- 振り分けが紙の上だけで行われるため、データ上でどれが先寸でどれがアイトレか分からない
- 起票待ち・CAD 待ちの状況が、紙のカゴを見ないと分からない
- 同じ注文が先寸とアイトレに分かれると、伝票に「先寸有・アイトレ有」と手書きして管理している

### 目的

1. 届いたメール・FAX をすべてシステムの「受付待ち」に集め、**受付No. ひとつで** 注文書・図面データ・受注を紐付ける
2. 先寸／アイトレの振り分けを **データとして残す**（DXF を 2 つの枠に分けて保存する）
3. 紙のカゴを画面に置き換える（受注登録待ち＝起票待ちのカゴ、CAD＝部品作成待ちのカゴ）
4. 受注登録の受注情報に、受付で入れた情報（売り先・工事名・納期・配達・納入先・加工場所）を初期値として入れる
5. ホームで各工程の目安納期を全社に共有する
6. **事務所（事務・CAD）をペーパーレスにする**（メールの表紙・振り分け用の図面・表紙のコピーを印刷しない）。**現場は今まで通り紙の運用** とし、現場用伝票は受注登録で印刷する

## 業務フロー

```
[メール/FAX/口頭] → ①受付待ち ──(受付登録・受付No.採番)──→ ②振り分け
                                                          ├─ 先寸   → ④受注登録待ち（加工場所ごと）→ 受注情報 → 注文内容 → 登録
                                                          └─ アイトレ → ③CAD（部品作成・CSV登録）→ ④受注登録待ち → …
```

1. **受付待ち**：メール・FAX が届くと受付待ち一覧に並び、シャーリング部の全員に通知される。口頭・電話の注文は「手動で受付を追加」で人が入れる（注文書 PDF は任意）
2. **受付登録**：1 件ずつ開き、受注情報（売り先・納入先・工事名・納期・配達など）・加工場所・至急を登録する。登録時に **受付No. を採番** する。見積・ミルシート・関係ないメールは区分して外す
3. **振り分け**：DXF を図面ソフトで開き、先寸／アイトレに分けた DXF を画面の 2 つの枠にドロップする。「振り分け完了」で、先寸は受注登録待ちへ、アイトレは CAD へ自動で入る。**元データはこの時点で削除** する
4. **CAD**：アイトレの DXF で部品を作成し、CSV を登録する。登録すると受注登録待ちに入る
5. **受注登録待ち（カゴ）**：加工場所（本社／A営業所／B営業所）ごとに、**至急 → 納期の早い順 → 納期の日付なし** で並ぶ
6. **受注登録**：一覧で選ぶと、受注情報に受付の内容が初期値として入る。受注情報で部材区分（DF / GPL / BH / SPL / 無分類）などを確定し、注文内容（明細）を入力して登録する。**受注No. は受付No.＋枝番**（`26-1003-1`）

受注はすべて受付を通す。口頭・電話の注文も「手動で受付を追加」から受付を作り、そこから受注登録する。受付を通さない受注は作らない（受注No. の形式を 1 つにするため）。

### 例外の運用

| ケース | 対応 |
| --- | --- |
| 振り分け後に「これは先寸だった」と見落としが見つかった | その図面だけ PDF にして、受注登録待ち一覧の「**受注登録待ちに追加**」から受付No. を指定して追加する。事務は新たに起票する（新しい枝番になる） |
| 口頭・電話の注文 | 受付待ちの「**手動で受付を追加**」で登録する。手書きの注文書を PDF 化してドロップしてもよいし、ファイルなしでも登録できる |
| 既存の受付に口頭で追加注文があった | 「受注登録待ちに追加」で、理由を「口頭での追加注文」にして追加する |
| 受注登録時に加工場所が変わった | 受注情報で加工場所を変更すると、その受付は変更先の受注登録待ちに移る。同時に受注登録まで済ませた受注は、変更先の出荷待ちに入る |
| 1 つの受付の中で納期が分かれる | 本当の納期は受注（枝番）ごとに持つ。受注情報で納期を変えればよく、受付の納期は書き換えない |
| CAD ソフト形式のファイルが届いた | 社内で開けない形式のため、今まで通り DXF に変換してから振り分けの枠に入れる |
| 受付の内容を間違えて登録した | 受付登録の処理区分「1 変更」で受付No. を呼び出して直す。「2 削除」は受注がまだ 1 件もない受付だけ |
| 振り分けを間違えた | 振り分け完了の前なら、枠のファイルを外して入れ直す。完了の後は振り分けを取り消さない（元データが消えているため）。見落とし・区分の誤りは「受注登録待ちに追加」で直す |
| 振り分け完了の後に元データを見返したい | 元データは振り分け完了で削除する（置き場所を圧迫しないため）。まれに見返したいときは、受付のメール（会社のメールソフトに残っている）の添付から確認する |

## 用語

| 用語 | 意味 |
| --- | --- |
| 受付 | 届いたメール・FAX・口頭注文の 1 件 |
| 受付No. | `YY-NNNN`（例：`26-1003`）。年ごとに 0001 から。**受付登録した時点で採番**（受付待ち・対象外には振らない） |
| 受注No. | 受付No.＋枝番（例：`26-1003-2`）。1 つの受付から複数の受注を登録できる |
| 受注情報 | 受付登録と受注登録で共通の入力欄（売り先・納入先・工事名・納期・配達など）。受付で入れた値が、受注の初期値になる |
| 加工場所 | 本社／A営業所／B営業所。受付登録時に割り振り、受注登録時に変更できる |
| 先寸 | シャー・ガス切断。振り分け後すぐ受注登録待ちへ |
| アイトレ | プラズマ・レーザー。CAD で部品作成・CSV 登録の後、受注登録待ちへ |
| 加工区分 | 1 つの受付を先寸／アイトレで分けた単位（テーブル名 `work_units`） |
| 振り分け | DXF を先寸／アイトレの枠に分けて保存すること。紙の振り分けの代わり |
| 元データ | メールに添付されていた DXF。振り分け完了で削除する（見返したいときは、受付のメールの添付から確認する） |
| 受注登録待ち | 起票待ちのカゴ。加工場所ごと |
| 部材区分 | DF／GPL／BH／SPL／無分類。部品ごとに受注を分けるときに使い、後の工程管理で利用する。**SPL はスプライスの受注** で、SPL を選ぶとスプライス専用の受注になる（本体の basic-design.md「スプライス専用の受注」） |
| 至急 | 受付登録時の印。受注登録待ち・CAD で最優先に並ぶ。納期種別の「最短出荷」とは別のもの（至急は事務所内の作業の順番、最短出荷は客先への出荷の約束） |
| 目安納期 | 工程ごとの「受注から出荷までの目安日数」と混雑度。ホームに表示 |

## 受注情報（受付と受注で共通の入力）

受付登録と受注登録は、同じ「受注情報」の入力欄を使い回す。受付で入れた値は、その受付から登録する受注の初期値になる。入力の形（番号の欄・キー操作）は本体の screen-design.md「入力方式」に従う。

| 項目 | 受付 | 受注 | 必須 | 初期値 |
| --- | --- | --- | --- | --- |
| 処理区分 | 0 新規 / 1 変更 / 2 削除 | 0 新規 / 1 変更 / 2 削除 | | 0 新規 |
| 番号 | 受付No.（新規は登録時に採番） | 受注No.（新規は登録時に枝番を採番） | | |
| 日付 | 受付日 | 受注日 | ○ | 今日（自動。変更できる） |
| 担当者 | 受付の担当者 | 受注の担当者 | ○ | ログイン中のユーザー（自動。変更できる） |
| 売り先 | ○ | ○ | **○** | 受注は受付の売り先 |
| 客先担当 | ○ | ○ | | 受注は受付の客先担当 |
| 入れ先（納入先） | 複数登録できる | 1 件 | | 受付は「0 売り先と同じ」、受注は受付の納入先の 1 件目 |
| 工事名 | ○ | ○ | | 受注は受付の工事名 |
| 納期（種別＋日付） | ○ | ○ | | 受付は「3 後報」（未定）、受注は受付の納期（下記） |
| 配達 | ○ | ○ | | 受付は「0 宵積み」、受注は受付の配達 |
| 加工場所 | ○ | ○ | | 受付はログイン中のユーザーの営業所、受注は受付の加工場所 |
| 至急 | ○ | ○ | | 受付はなし（0 通常）、受注は受付の至急（PR 9 で受注にも持たせた。現場で優先して加工してもらうため） |
| 部材区分 | — | ○ | | 0 無分類 |
| 継手番号・ショット | — | 部材区分が SPL のときだけ | | ショットは 1 有 |

必須は売り先だけとする。日付・担当者・加工場所は自動で入るため、入力しなくても空にはならない。届いた時点では決まっていない項目が多いため、受付の段階で入力を強制しない。

担当者は自社の担当者（受付や起票をした人）であり、客先の窓口担当（客先担当）とは別の項目である。ログイン中のユーザーが初期値だが、代わりに入力した場合などに変更できる。

### 納期の決まり

- 受付登録では、納期の初期状態は「3 後報」（日付なし＝未定）。分かっているときだけ種別と日付を入れる
- 受注登録の納期の初期値は、受付に日付があれば「1 確定」＋その日付、日付がなければ「3 後報」。受付で「2 仮納期」「4 最短出荷」を選んでいた場合は、その種別をそのまま初期値にする
- 1 つの受付の中で納期が分かれることがあるため、本当の納期は受注（枝番）ごとに持つ。受付の納期は、受注の初期値と、受注登録待ち・CAD の並び順に使う **代表の納期** とする
- 受注登録で納期を変えても、受付の納期は書き換えない

### 入れ先の決まり

- 受付には入れ先を複数登録できる。「0 売り先と同じ」も 1 件として登録できる
- 受注の入れ先は 1 件。初期値は受付の入れ先の 1 件目
- 受注の入れ先の番号の欄に打つ数字は、本体と同じく納入先マスタのコード（0 は売り先と同じ）。受付に登録した入れ先は、「/」の一覧の先頭に並べて ↑↓ と Enter で選ぶ。受付の入れ先が 1 件なら Enter だけで進める

### 処理区分

受付登録・受注情報のどちらも、処理区分で新規・変更・削除を切り替える。

| 処理区分 | 受付登録 | 受注情報 |
| --- | --- | --- |
| 0 新規 | 受付待ちの 1 件（または手動で追加した受付）を登録し、受付No. を採番する | 受注登録待ちの加工区分から始め、登録時に枝番を採番する |
| 1 変更 | 受付No. を入力して呼び出し、受注情報を直す。登録済みの受注は書き換えない | 受注No. を入力して呼び出し、受注情報と注文内容を直す |
| 2 削除 | 受付No. を入力して呼び出し、論理削除する。受注が 1 件でもある受付は削除できない | 受注No. を入力して呼び出し、論理削除する。出荷実績がある受注は削除できない（本体の screen-design.md「受注の削除」） |

受付の「2 削除」は、受付登録した後に取り消すためのものである。受付待ちのメールのうち注文ではないものは、従来どおり「対象外」に区分する（削除ではない）。

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-01 | 受付待ち一覧 | 受付待ちを新しい順に表示。行を選ぶと右側に本文・添付を表示。「受付登録」「見積・ミルシート」「対象外」に振り分ける |
| F-02 | 手動で受付を追加 | 経路（口頭・電話／来社／メール転送漏れ／その他）、受付日時、注文書 PDF・DXF（任意）、メモで受付待ちに追加し、そのまま受付登録へ |
| F-03 | 受付登録 | 受注情報（上記）・至急を登録。受付No. を採番し、登録者・登録日時を記録。処理区分で変更・削除もできる |
| F-04 | 対応中の表示 | 誰かが受付待ちの 1 件を開くと、他の人の画面に「○○さんが対応中」と表示（二重登録防止） |
| F-05 | 新着通知 | 受付待ちに 1 件追加されたら、シャーリング部の全員の画面に通知（右上の通知・ベルの未読数・メニューの件数） |
| F-06 | 振り分け | 元データ一覧と「先寸」「アイトレ」の 2 つの枠。枠には複数ファイルをドロップ可。同じ名前は差し替え。「振り分け完了」で元データを削除し、先寸→受注登録待ち、アイトレ→CAD へ |
| F-07 | DXF を開く | 「開く」で DXF をダウンロードし、パソコンの関連付けで図面ソフトが起動する |
| F-08 | CAD | アイトレの加工区分を加工場所ごとのタブ（最初はユーザーの営業所）に、至急→納期順に表示。「作業開始」で担当者を記録、CSV をドロップして登録すると受注登録待ちへ。作業開始の取り消し・CSV の入れ直しと外す操作。作業中のまま長くたった行を目立たせる（CSV の入れ忘れ） |
| F-09 | 受注登録待ち一覧 | 加工場所ごとのタブ。至急→納期→日付なしの順。区分（先寸／アイトレ）、追加の理由（見落とし追加・口頭）、受付の担当者を表示 |
| F-10 | 受注登録待ちに追加 | 受付No. を入力（受付情報を表示）→ 理由（振り分けの見落とし／口頭での追加注文／その他）→ 区分（先寸／アイトレ）→ PDF・DXF（任意） |
| F-11 | 受注情報 | 受付の受注情報を初期値として表示（修正可）。受注No. は登録時に枝番で採番し、画面には次の枝番と同じ受付の登録済みの受注を表示。部材区分・加工場所を確定する |
| F-12 | 注文内容 | 本体の受注登録画面の ② 注文内容（明細は 1 件 1 行。その下にスタンプ・フリーコメント）。注文書 PDF は画面の左のパネルに表示する |
| F-13 | 起票完了 | 1 つの加工区分から複数の受注を登録できるため、「この区分の起票を完了」で受注登録待ちから外す。間違って作った区分も、受注登録待ちの一覧から同じ操作で外す（外した区分と起票を終えた区分は、その区分の受注があるかどうかで見分ける） |
| F-14 | 納期連絡 | 工程ごとの目安日数・混雑度（通常／やや混雑／混雑／要相談）・補足、部署メッセージ（表示期限つき）を設定し、ホームに公開。更新履歴を残す |
| F-15 | ホームの目安納期 | 加工部（切断・穴あけ・プレス・DS・ショット・CT）とシャーリング部（レーザー・プラズマ）の目安納期とメッセージを表示 |
| F-16 | 共通レイアウト | ネイビーのヘッダーと開閉できるサイドメニュー。受注登録の画面では初期状態で閉じる（本体の screen-design.md「共通レイアウト」） |
| F-17 | ログイン | 社員No.＋パスワードでログインする |

| 権限 | 本体の 3 ロール（事務・現場・管理者）と RLS をそのまま使う。受付のテーブルは事務・管理者が読み書きできる。現場は使わない |
| 採番 | 受付No.・受注No. の枝番は DB の関数で採番し、同時操作でも重複しないこと。採番のカウンターと関数は Data API で公開しない `private` スキーマに置く |
| ファイル | Supabase Storage の非公開バケット。DB にはファイルの情報だけを持つ（`intake_files`）。受注に関わるファイルはすべてここに持ち、本体の `attachments` は使わない。**元データは振り分け完了で削除** し、容量を抑える |
| 通知 | Supabase Realtime で、システムを開いている人に即時に届く |
| 記録 | 作成者・更新者・日時を記録。業務データは物理削除しない（ファイルの元データは例外） |
| 操作性 | 受注情報はテンキー中心のコード入力（本体の方針）。受付No.・コードはキーボードだけで入力できる |
| 画面 | 本体と同じく 1280 × 1024 を前提とする。色はネイビー（#1b365d）をアクセントとし、赤（#c0392b）は至急・要相談・重要・必須のみに使う（本体の screen-design.md「共通レイアウト」） |

## MVP の対象外（運用で対応）

- 1 つの受付の一部だけ別の営業所で加工する（受付を分けて登録する）
- 共有フォルダとシステムの自動同期
- 受付〜受注登録待ちの範囲の印刷。受注登録待ちと CAD の画面がカゴと表紙の役割を果たす
- 現場は今まで通り紙で運用する。CAD はネスティング後のデータと用紙を現場に渡し、現場用伝票・加工図面は受注システム側の機能（現場用伝票の印刷・加工図面の印刷）で印刷する

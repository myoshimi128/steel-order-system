## 共通の部品

### DocumentViewer（S-04c・S-06c の左側）

タブ「注文書（PDF）」「図面データ（件数）」を持つ。

- 注文書：PDF を画面内に表示する（ページ送り・拡大・別ウィンドウ）。ページ送り・拡大は自作せず、ブラウザの PDF の表示機能を iframe に埋め込んで使う。PDF が複数あれば上の選択で切り替える。表示には期限つき（1 時間）の署名付き URL をサーバーで作って使う（バケットは非公開）
- 図面データ：その画面で扱う区分の DXF の一覧と「開く」「すべて開く」。「すべて開く」（「すべて図面ソフトで開く」）は 2 件以上あるときに出す（PR 6）。ダウンロード用の URL をまとめて作り、少しずつ間を空けて順にダウンロードする。初回だけ、ブラウザが複数のファイルのダウンロードを許可するか聞いてくる（画面に案内を出す）
- PR 5 で受付登録（S-04c）のために作った（「実装の順序」では PR 6 の予定だった）。受注登録の注文書のパネルへの組み込みは PR 9。実装：`components/intake/document-viewer/document-viewer.tsx`、添付の一覧と「開く」は `components/intake/intake-file-list.tsx`・`lib/intake/use-file-opener.ts`

受注登録（S-06c・S-06d）では、DocumentViewer を「注文書のパネル」として 2 つの画面の左に置く。幅をドラッグで変えられ、F2 で開閉できる（本体の screen-design.md「受注登録画面」の「注文書のパネル」）。事務所の PC は画面 1 枚のため、別ウィンドウではなく画面の中で表示する。

### DXF を開く

- 署名付き URL を `download` 指定で発行し、ブラウザでダウンロードする → パソコンの関連付けで図面ソフトが起動する。URL は「開く」を押すたびにサーバーで作る（有効 60 秒。Server Action の `createIntakeFileDownloadUrl`）。PDF の「開く」は新しいタブで表示する
- 初回だけ、ブラウザで「この種類のファイルを常に開く」を設定する（ヘルプの文言を画面に表示する）
- ダウンロードするときのファイル名：`{受付No.}_{区分}_{元のファイル名}`（`lib/intake/file-name.ts`）

### 受注情報の入力欄（S-04c・S-06c で共通）

受付登録（S-04c）と受注情報（S-06c）は、同じ入力欄のコンポーネントを使い回す。項目と初期値は basic-design.md「受注情報（受付と受注で共通の入力）」を参照。入力は本体の「入力方式」（番号の欄＋名称、Enter で次へ、「/」または End で一覧）に従う。

| 行 | 受付登録（S-04c） | 受注情報（S-06c） |
| --- | --- | --- |
| 1 | 処理区分・受付No.・受付日・担当者 | 処理区分・受注No.・部材区分（SPL のときは継手番号・ショット）・受注日・担当者 |
| 2 | 売り先・客先担当 | 売り先・客先担当 |
| 3 | 入れ先（複数。「＋入れ先を追加」で行を増やす） | 入れ先（1 件） |
| 4 | 工事名 | 工事名 |
| 5 | 納期（種別＋日付）・配達 | 納期（種別＋日付）・配達 |
| 6 | 加工場所・至急 | 加工場所 |

- Enter の順路は左上から右下へ。最後の欄で Enter を押すと、画面の確定ボタン（「受付No. を発行して登録」「受注情報を確定して次へ」）へ移る
- 受付No.・受注No. の欄では「-」をハイフンとして入力する（テンキーの「-」でハイフンを打てるようにするため）。入力は `lib/intake/intake-no.ts` で正規化する（`26-1003` / `261003` / `26 1003` → `26-1003`、`26-1` → `26-0001`。ハイフンなしは連番 4 桁以上のときだけ受け付ける）
- 担当者は社員No. で入力する。「/」の一覧から選ぶこともできる。初期値はログイン中のユーザー
- 加工場所は番号の欄（1 本社 / 2 A営業所 / 3 B営業所）。初期値が必ず入るため、番号 0 は使わない
- 受付から自動で入った値は薄い青で表示し、手で直した欄は通常の色に戻す（受付の値と違うことが分かるようにする）

**入れ先（受付）**

- 行ごとに番号の欄を 1 つ置き、納入先マスタのコードを打つ（0 は売り先と同じ）。初期状態は「0 売り先と同じ」の 1 行
- 「＋入れ先を追加」で行を増やす。行ごとに削除できる。並び順を保存する
- 同じ納入先を 2 行入れることはできない

**入れ先（受注）**

- 番号の欄は 1 つ。打つ数字は納入先マスタのコード（0 は売り先と同じ）
- 初期値は受付の入れ先の 1 件目
- 「/」の一覧の先頭に、受付に登録した入れ先を「受付 1」「受付 2」…の印を付けて並べ、その下に納入先マスタの検索を出す。↑↓ と Enter で選ぶ
- 受付の入れ先が 1 件なら、Enter だけで進める

## 画面

### S-00 ログイン

- 社員No.（必須）とパスワード（必須）を入力する
- 社員No. から、決まった形のメールアドレスを作って Supabase Auth に渡す（本体の basic-design.md「権限設計」）
- 失敗したときは「社員No. またはパスワードが正しくありません」と表示する（どちらが違うかは区別しない。社員No. の形の違い・無効のユーザーも同じ文）。空のまま押したときは「社員No. とパスワードを入力してください」。エラーのあとも社員No. の欄の値は残す
- 社員No. は小文字・全角で打ってもよい（大文字・半角にそろえる）
- 見た目は画面イメージ「00 ログイン」に合わせる：上にネイビーの帯、地は薄い格子柄。中央にロゴ・システム名・英字の副題、その下に上の縁がネイビーのカード（見出し「ログイン」、社員No.・パスワードの欄に必須の赤い＊、パスワードの表示の切り替え、ネイビーのログインのボタン）。カードの下に注意書き、画面の下端に著作権の表示と問い合わせ先
- 実装：`app/login/page.tsx`、`components/login/`（ロゴ・フォーム・項目名・パスワードの欄・下端の帯）、`app/actions/auth.ts`（`login`）

### S-01 ホーム

- 上部：あいさつ（「おはようございます、○○さん」）と今日の日付（例：2026年10月19日（月））。あいさつは日本時間の時刻で変える（5〜10 時台「おはようございます」、11〜16 時台「こんにちは」、それ以外「こんばんは」。`lib/home/greeting.ts`）
- 左：社内連絡。**Phase 1 は枠と見出しだけを出し、「社内連絡は準備中です」と表示する**。お知らせの登録・一覧は Phase 2（F-24）。画面イメージのお知らせはサンプルのため、コードには持たない
- 右：目安納期。加工部・シャーリング部のカード（工程・日数・混雑度の印・部署メッセージ・更新日時と更新者）。凡例を表示する
- 部署メッセージは、表示期限（`expires_on`）の日まで表示し、次の日から表示しない。期限が空なら表示し続ける
- 混雑度が「要相談」の工程と、日数がまだ入っていない工程は、日数の代わりに「—」を表示する
- 混雑度の印の色：通常は白地に枠、やや混雑は薄いネイビー、混雑はネイビー、要相談は赤
- 更新日時と更新者は、その部署の最新の更新履歴（`lead_time_history`）から出す
- 画面イメージ「01 メインメニュー」との違い：社内連絡の中身と「すべて見る」は出さない。ベルは赤い点ではなく未読の数を出す
- 実装：`app/(main)/page.tsx`、`components/home/`、カード・混雑度の印・凡例は納期連絡のプレビューと共通（`components/lead-time/`）。読み込みは `lib/lead-time/load-lead-times.ts`

### S-02 部署ホーム（シャーリング部）

- 件数のカード：受付待ち／受注登録待ち／本日納期／CAD 作業待ち・作業中（PR 8）
  - 受付待ちは全部の営業所の分（受付登録の前は加工場所が決まっていないため）。ほかの 3 つは、ログイン中のユーザーの営業所の分（管理者は全部の営業所。営業所が空のユーザーも全部。`lib/intake/queue.ts` の `countScopeSiteId`）
  - 本日納期は、今日が納期で完了していない受注の数
  - カードを押すと、その一覧（受付待ち一覧・受注登録待ち一覧・CAD）を開く。本日納期は一覧の画面（受注管理）がまだないため押せない
  - 受付のテーブルを読めないロール（現場）では、受付・受注登録待ち・CAD の件数に「—」を出す
- 部署内連絡・部署タスクは **Phase 2**。今は枠と見出しだけを出し、「準備中」と表示する（ホームの社内連絡と同じ）
- ボタン：受付登録へ・受注登録へ（受注登録待ちの一覧）
- 見出しの上に営業所の名前（管理者は「全営業所」）
- 画面イメージ「02」との違い：4 枚目のカード「加工図面 未発行」は、加工図面の発行の機能ができるまで「CAD 作業待ち・作業中」にする。部署内連絡・部署タスクのサンプルの中身と投稿の欄は出さない。サイドメニューの部署の枠の人数は出さない
- 実装：`app/(main)/shearing/page.tsx`、`components/shearing/`（カード・準備中の枠）、件数は `lib/shearing/load-shearing-summary.ts`

### S-03 納期連絡

- 工程ごとに：目安日数（営業日・整数 0〜99）、混雑度（通常／やや混雑／混雑／要相談の 4 択）、補足（ホームには出さない）。工程の追加・並べ替え（↑↓のボタン）
  - 「要相談」のときは日数を入れない（空で保存し、ホームでは「—」）。それ以外は日数が必須
  - 追加した工程は、名前を入れる。同じ部署に同じ名前の工程は作れない。公開する前なら × で追加を取り消せる
  - **工程の削除・非表示はできない**（工程がなくなることは基本的にないため）。工程の削除・非表示は、必要になったら追加する。既存の工程の名前も変えない
- 部署メッセージ（文章。200 文字まで）と表示期限（日付。受注登録と同じ打ち方の欄で、月日 4 桁で入れられる）。メッセージを空にすると、表示期限も空にする
- 右：ホームでの表示のプレビュー（入力中の内容がすぐ反映される）、更新履歴（新しい順に 10 件）
- 「ホームに公開」で保存する（保存＝公開。下書きはなし）。保存のたびに `lead_time_history` に要約を 1 行残す（例：「レーザー 3→2営業日、プラズマを「やや混雑」に変更、メッセージを更新」。`lib/lead-time/summary.ts`）。何も変えていなければ「変更がありません」として公開しない
- **画面を開いた後にほかの人が先に公開していたら、上書きせずにエラーにする**（「ほかの人が先に公開しました。…画面を開き直して…」）。気づかずにほかの人の変更を消してしまうのを防ぐため。開いた時点の最新の更新履歴と、公開する時点の最新の更新履歴を比べる
- 「元に戻す」で、最後に公開した状態に戻す
- 編集できるのは事務・管理者（`publish_lead_times` と RLS でも強制する）。部署では制限しない（権限はロールで決める）。現場のユーザーには同じ画面を「閲覧のみ」で出す（入力できず、ボタンを出さない）
- 加工部の納期連絡も同じ画面を部署の切り替え（シャーリング部 / 加工部のタブ。`?dept=processing`）で使う。入り口はシャーリング部のメニューの「納期連絡」だけ（Q-7 の決定）。公開していない入力があるときは、切り替える前に確かめる
- 画面イメージ「03 納期連絡」との違い：上に部署の切り替えを足す。サイドメニューの部署の枠の人数（「本社 15名」）と、業務メニューの件数のバッジは出さない。表示期限の欄にカレンダーのアイコンは付けない
- 実装：`app/(main)/shearing/lead-time/page.tsx`・`actions.ts`（`publishLeadTimes`）、`components/lead-time-editor/`、入力の状態は `lib/lead-time/use-lead-time-editor.ts`、入力の確認は `lib/lead-time/draft.ts`

### S-04a 受付待ち一覧

```
┌ 受付登録 ───────────────────────────────── [＋ 手動で受付を追加] ┐
│ ┌ タブ: 受付待ち(6) / 受付登録済(38) / 見積・ミルシート / 対象外 ┐ ┌ メールのプレビュー ┐ │
│ │ 検索（差出人・件名）                          新しい順 │ │ 差出人・受信日時     │ │
│ │ NEW  受信日時  経路  差出人  件名  添付              │ │ 件名・本文          │ │
│ │ …                                                  │ │ 添付ファイルの一覧   │ │
│ │                                                    │ │ [対象外][見積・ミルシート]│ │
│ └────────────────────────────────┘ │ [この内容で受付登録 →]│ │
│                                                         └──────────┘ │
└──────────────────────────────────────────────┘
```

- タブ：受付待ち／受付登録済（＝振り分け待ち）／見積・ミルシート／対象外
- 列：NEW の印（未読）・受信日時・経路・差出人・件名・添付（PDF／DXF n／要変換 n）
- 行を選ぶと右にメールのプレビュー（差出人・受信日時・件名・本文・添付の一覧）。変換が必要なファイルには「DXF への変換が必要」と表示する
- 右下：対象外／見積・ミルシート／**この内容で受付登録** → S-04c
- 行を選んだ時点で `handling_by` を自分にする（`claim_intake()`。空き・自分・30 分過ぎのときだけ自分にするため、2 人が同時に開いても 1 人に決まる）。ほかの行に移った・画面を閉じたときに外す（`release_intake()`）。他人が対応中の行は「○○さんが対応中」と表示する（30 分で自動解除。表示のときに開始から 30 分たったものは無効とみなす。`lib/intake/handling.ts`）
- 他人が対応中でも、見ることと操作は止めない。「この内容で受付登録」を押したときだけ「○○さんが対応中です。続けて受付登録しますか」と確かめる。二重登録そのものは、DB の関数が受付の状態を見て止める
- タブは URL の `?tab=` で切り替える。受付待ち・受付登録済には件数を出す。一覧は新しい順に 200 件まで
- NEW の印は「この受付の通知を自分がまだ読んでいない」とき（`notification_reads`）。行を選ぶと、その受付の通知を既読にして印を消す（ベルの未読の数も減る）
- 検索の欄は差出人・件名（と、メモ・売り先・工事名・受付No.）で、読み込んだ行の中から絞り込む
- 添付の「要変換」は「元データ（`original`）のうち DXF でないもの」と判定する（拡張子の一覧は持たない。`lib/intake/attachments.ts`）
- 右側：本文がない受付（FAX・手動で追加した受付）はメモを出す。タブごとの操作は次のとおり
  - 受付待ち：対象外／見積・ミルシート／この内容で受付登録（どちらの区分も確かめてから行う。見積・ミルシートは受付No. を発行して知らせる。`classify_intake()`）
  - 受付登録済：受付No.・売り先・工事名・納期・加工場所を出す。「受付の内容を直す」（処理区分 1 変更）と「振り分け →」（S-04d）
  - 見積・ミルシート：「削除する」（処理区分 2 削除）
  - 対象外：「受付待ちに戻す」
- 上に「受付No. で呼び出す（変更・削除）」（`/intake/register?type=1`）と「＋ 手動で受付を追加」を置く。受付登録・変更・削除の後は、この画面に戻って結果を上に知らせる（`?notice=…&no=…`。`lib/intake/tabs.ts`）
- 一覧の下に「電話注文など、メール・FAX 以外の受付は『手動で受付を追加』から登録できます」と案内する
- 新着の通知が届くと、右上にトーストを表示し、一覧に行が追加される（受付の変更を Realtime で受け取ったら、画面を読み直す。短い間の変更はまとめて 1 回。`lib/intake/use-intake-changes.ts`）。ほかの人の対応中の表示・件数も同じ仕組みで変わる
- 通知のベルの一覧・トーストを押すと、その通知を既読にして `/intake?selected={受付の id}` へ移り、その行を選んだ状態で開く
- 画面イメージ「04a」との違い：受付登録済のタブの行は、右側の「振り分け →」から S-04d を開く（行を押すと、まず右側に中身を出す）。右側に「受付の内容を直す」を足す。上に「受付No. で呼び出す（変更・削除）」を足す。サイドメニューの部署の枠の人数と、CAD・受注登録の件数のバッジは出さない（それぞれの PR で出す）
- 実装：`app/(main)/intake/page.tsx`・`actions.ts`、`components/intake/inbox/`（画面・タブ・一覧・右側）、状態と操作は `lib/intake/use-intake-inbox.ts`、読み込みは `lib/intake/load-intakes.ts`

### S-04b 手動で受付を追加（モーダル）

- 経路（口頭・電話／来社／メール（転送漏れ）／その他）、受付日時（初期値：今）、注文書（PDF・DXF、任意・複数）、メモ
- 「追加して受付登録へ」：`waiting` の受付を作成 → S-04c へ
- 経路の「メール（転送漏れ）」は経路 `mail` として保存する
- 受付日時は、受注日と同じ打ち方の日付の欄と、4 桁の時刻の欄（1040 → 10:40）。日本の時刻として保存する（`lib/intake/received-at.ts`）
- 注文書は枠にドロップするか、枠を押して選ぶ。入れられるのは PDF と DXF で、1 ファイル 50MB まで（未決 Q-4）。PDF は注文書（`order_pdf`）、DXF は元データ（`original`）として保存する。同じ名前のファイルを入れ直すと差し替える
- ファイルは、受付を作ってからブラウザで Storage に置く（「ファイルの保存」は table-design.md）。一部のファイルを置けなかったときは、受付はできているため、どのファイルかを出して「このまま受付登録へ」で進めるようにする
- 受付を作ると、メールと同じくシャーリング部への新着の通知が出る（DB のトリガー）
- 画面イメージ「04b」との違い：受付日時の欄にカレンダーのアイコンは付けず、日付と時刻の欄にする

- 入力欄は「受注情報の入力欄」（上記）。必須は売り先だけ
- 至急は **番号の欄（0 通常 / 1 至急、初期値 0）**。テンキーから手を離さずに入力できるようにするため、チェック欄にはしない（部材区分 SPL・ショットを番号の欄にしたのと同じ考え方）。1 のときは欄の枠と名称を赤くする。受注登録待ち・CAD の先頭に並ぶ
- 担当者は社員No. の番号の欄（「/」で一覧。初期値はログイン中のユーザー）。受付日は受注日と同じ打ち方の日付の欄
- 「受付No. を発行して登録」：`save_intake(…, p_register => true)` を呼ぶ（受注情報の保存・入れ先の入れ直し・`register_intake()` による採番と `registered`・登録者の記録を 1 つの transaction で行う）。登録の後は、そのまま振り分けの画面（S-04d）へ進み、発行した受付No. を上に知らせる（「受付No. 26-0003 を発行して受付登録しました。続けて振り分けます」）
- 登録ボタンの下に「登録すると、振り分けのあと『本社』の受注登録待ちに入ります」のように、加工場所に応じた行き先を表示する
- 左の DocumentViewer で、注文書と添付の DXF を確認できる
- 開いている間は自分を対応中にする（S-04a と同じ）。ほかの人が対応中なら上に「○○さんが対応中」を出し、登録のときに「このまま登録しますか」と確かめる（止めはしない）
- 必須の欄が空・存在しない番号などのときは、欄を赤い枠にして最初の欄へカーソルを移し、下に「入力に誤りがあります」と出す
- ほかの人が先に登録していた（受付待ちでなくなっていた）ときは、保存せずにエラーにする
- 処理区分 1 変更：受付No. を入力して呼び出し、入力欄を直して「変更を保存」（`save_intake(…, p_register => false)`）。登録済みの受注は書き換えない。呼び出せるのは受付登録済・振り分け完了・完了の受付（見積・ミルシートは変更しない）
- 処理区分 2 削除：受付No. を入力して呼び出し、内容を表示して確認のうえ論理削除する（`delete_intake()`）。呼び出せるのは受付登録済・振り分け完了・完了・見積の受付。受注が 1 件でもある受付の削除の禁止は、受注と受付をつなぐ PR 9 のトリガーで行う（今は受注に受付の列がないため）
- 処理区分・受付No. の欄で Enter を押すと、その区分・番号の URL（`/intake/register?type=…&no=…`）へ移り、サーバーが受付を読み直す。受付No. は `lib/intake/intake-no.ts` で正規化する。処理区分 0 を選ぶと受付待ち一覧へ戻る（新規は一覧で受付を選んでから始める）
- 受付待ちでない受付を `/intake/[id]` で開くと、登録済みなら変更の画面へ移す
- 画面イメージ「04c」との違い：処理区分・受付日・担当者・客先担当・配達の欄を足す（「受注情報の入力欄」の 6 行）。必須の印は売り先だけ（画像は工事名・納期・納入先にも付いている）。納期はカレンダーと「宵積み・納期未定」のチェックではなく、種別＋日付と配達の番号の欄。至急はチェックではなく番号の欄。加工場所は番号の欄と選択肢のボタンを並べた形（受注情報と同じ）。PDF のページ送り・拡大はブラウザの機能を使う
- 実装：`app/(main)/intake/[id]/page.tsx`（新規）・`app/(main)/intake/register/page.tsx`（変更・削除）・`actions.ts`、`components/intake/register/`（画面・入力欄・入れ先の行・至急の欄・削除の確認）、入力の状態は `lib/intake/use-intake-form.ts`、初期値と確認は `lib/intake/intake-form.ts`。納期・配達・加工場所の欄は受注情報の部品（`components/order-entry/header/`）を使い回す

### S-04d 振り分け

```
┌ 振り分け  26-1003  A製作所  ○○ポンプ設備工事（その2）  納期 10/03 ────────────┐
│ ┌ 元データ（メール添付）  振り分け完了で自動削除 ┐ ┌ 振り分け ───────────────────┐ │
│ │ [すべて図面ソフトで開く]                     │ │ ┌ 先寸 3ファイル ┐ ┌ アイトレ 2ファイル ┐ │ │
│ │ 組立_全部品.dxf  複数部品  分割して保存済 [開く] │ │ │ …            │ │ …               │ │ │
│ │ PL9-297×1530.dxf          → 先寸   [開く] │ │ │ ここにドロップ  │ │ ここにドロップ    │ │ │
│ │ PL12-340×438.dxf          未振り分け [開く] │ │ │ →受注登録待ちへ │ │ →CAD（部品作成待ち）│ │ │
│ │ （操作の案内）                             │ │ └────────┘ └─────────┘ │ │
│ └──────────────────────┘ │ 未振り分けの元データが 1 件あります [一覧に戻る][振り分け完了 →] │ │
│                                                 └─────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- 左：元データの一覧（各行に「開く」、状態：→先寸／→アイトレ／分割して保存済／未振り分け）、「すべて図面ソフトで開く」
- 右：**先寸の枠** と **アイトレの枠**。複数のファイルをドロップできる。元データの行を枠へドラッグしてもよい（＝その元データをそのまま複製して振り分け済みにする）
  - 1 つの DXF に複数の部品 → 図面ソフトで先寸の部品だけ残して「名前を付けて保存」→ 先寸の枠へ。アイトレも同様
  - 1 部品ずつの DXF → そのまま枠へドラッグ
  - 同じ枠に同じ名前のファイルを入れたら差し替え
- 元データの状態の表示：元データと同じ名前のファイルが枠にあれば「→先寸／→アイトレ」。分割したファイルとの対応は、人が「分割して保存済」にチェックする
- 「振り分け完了」：`complete_split()` を呼ぶ
  - 先寸の枠にファイルがあれば `sakisun`（ready）、アイトレの枠にあれば `aitore`（cad_waiting）の加工区分を作り、枠のファイルをそれぞれに紐付ける
  - **図面が 1 つもない注文（FAX・口頭）**：ボタン「図面なしで 先寸として登録」「図面なしで アイトレとして登録」を表示する
  - 元データ（kind=`original`）を論理削除し、アプリが Storage から実ファイルを削除する
  - 未振り分けの元データがある場合は確認のダイアログ（「削除されます。よろしいですか」）を出す
- 枠は **入れた時点で保存する**（「一時保存」のボタンは置かない）。画面を離れても枠の中身は残り、後から続きができる。受付の状態は振り分け完了まで `registered` のまま
- 左下に操作の案内を表示する（複数部品の DXF は図面ソフトで分けて保存、1 部品ずつの DXF はそのままドラッグ、要変換のファイルは DXF に変換してから）
- 入口：受付待ち一覧の受付登録済のタブの「振り分け →」と、受付登録（処理区分 0 新規）の後。受付登録済でない受付（振り分け完了・完了など）は振り分けの画面を出さない
- 上に受付No.・至急・売り先・工事名・納期と「注文書を開く」（注文書の PDF を新しいタブで開く）
- 枠への入れ方は 2 通り。どちらも、実物を Storage に置いてから行を作る（`add_split_file()`。同じ枠に同じ名前があれば、前の行を論理削除して差し替え、前の実物を消す）
  - パソコンからファイルをドロップ（枠を押して選んでもよい）。入れられるのは PDF と DXF で、1 ファイル 50MB まで
  - 元データの行をドラッグ：サーバーが Storage の中で元データを複製して枠に入れる（元データは振り分け完了で消えるため、移動ではなく複製。同じ元データを両方の枠に入れてもよい）
- 枠のファイルは「開く」と ×（外す。`remove_split_file()` で論理削除し、実物を消す）。元データと名前が違うファイル（図面ソフトで分けて保存したもの）には「分割」の印を付ける
- 「分割して保存済」は、枠に同じ名前のファイルがない元データの行にだけ出すチェック（`intake_files.split_done`。`set_original_split_done()`）
- 下に「未振り分けの元データが ○ 件あります」（なければ「元データ ○ 件はすべて振り分け済みです」）
- 2 つの枠がどちらも空のときは、「振り分け完了」の代わりに「図面なしで先寸として登録」「図面なしでアイトレとして登録」を出す
- 「振り分け完了」を押すと、「先寸 ○ ファイル・アイトレ ○ ファイルで振り分けを完了します」と件数を出して確かめる（未振り分けの元データがあれば、その数と「削除されます」も出す）。完了すると受付登録済の一覧に戻り、結果を上に知らせる
- 振り分け完了の後は、振り分けを取り消さない（元データが消えているため）。見落とし・区分の誤りは、受注登録待ち一覧の「受注登録待ちに追加」（S-06b。PR 8）で直す
- 元データは振り分け完了で論理削除し、Storage の実物も消す（置き場所を圧迫しないため）。まれに元データを見返したいときは、受付のメール（会社のメールソフトに残っている）の添付から確認する
- 振り分け完了で CAD などへの通知は出さない（CAD の担当もシャーリング部で、CAD の一覧が自動で更新されるため）。CAD のメニューの件数のバッジは PR 7 で出した。受注登録待ちは PR 8 で出す
- 画面イメージ「04d」との違い：元データをまとめて開くボタンは「すべて図面ソフトで開く」にする（実在の製品名を使わない）。案内の形式の名前は「DXF への変換が必要なファイル」にする。「一時保存」のボタンは置かず、「一覧に戻る」にする。元データの「複数部品」の印は出さない（ファイルの中身から判定できないため）。「分割して保存済」は人がチェックする欄。見出しに「注文書を開く」を足す
- 実装：`app/(main)/intake/[id]/split/page.tsx`・`actions.ts`、`components/intake/split/`（画面・元データの一覧・枠）、状態と操作は `lib/intake/use-split-board.ts`、元データの状態・未振り分けの数・完了の確認の文は `lib/intake/split.ts`、「すべて開く」は `lib/intake/use-file-opener.ts`

### S-05 CAD

```
┌ CAD ─────────────────────────────────────────────────────────────┐
│ ┌ [本社 4] [A営業所 1] [B営業所 0] ───────────────┐ ┌ CAD 作業中 [アイトレ][先寸あり] ┐ │
│ │  [作業待ち・作業中 4] [CSV 登録済 1]              │ │ 26-1003  A製作所                 │ │
│ │ [受付No.・売り先で検索]   並び順: 至急 → 納期の早い順 │ │ 工事名・納期・加工場所・担当       │ │
│ │ 納期  受付No. 売り先／工事名  図面  状態／担当      │ │ 図面データ（DXF 3件）[すべて…]  │ │
│ │ 10/03 26-1003 A製作所…    [DXF] 作業中 田中 [CSV を登録] │ │ [注文書 PDF]                     │ │
│ │                                1日2時間経過       │ │ 部品作成後の CSV（ドロップ枠）    │ │
│ │ 10/24 26-1006 G工業…      [DXF] 未着手    [作業開始] │ │                                │ │
│ │ （作業開始の案内）                               │ │ ネスティング後のデータと用紙は…    │ │
│ └──────────────────────────────┘ └────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

- タブは 2 段
  - 上：加工場所（本社／A営業所／B営業所）。受注登録待ちと同じ部品（`components/intake/site-tabs.tsx`・`lib/intake/site-tabs.ts`）。URL の `?site=`（営業所のコード）で切り替え、指定がなければ **ログイン中のユーザーの営業所のタブ** を開く（営業所ごとに CAD の担当がいるため）。件数は作業待ち・作業中の数で、サイドメニューの「CAD」のバッジと同じ数え方（開いたタブの件数とバッジがそろう）
  - 下：作業待ち・作業中（`cad_waiting`・`cad_working`）／CSV 登録済（`ready`。起票前。起票完了すると一覧から消える）。開いている加工場所の件数を出す。URL の `?tab=csv` で切り替える（加工場所の `?site=` は残す）
  - 選んだ行は `?unit=`（加工区分の id）に持つ。別の加工場所・別の状態のタブの行なら、一覧の先頭を選ぶ
- 列：納期（至急の印）・受付No.・売り先／工事名・図面（DXF。押すと開く、2 件以上ならまとめて開く）・状態／担当・操作（作業待ちは「作業開始」、作業中は「CSV を登録」）。1280px で右のパネルと並べるため、売り先と工事名、状態と担当は 1 つの列に 2 段で出す。加工場所は上のタブで分けているため列には出さない（右のパネルには出す）
- 並び順：作業待ち・作業中は「並び順」（後述）のとおり。CSV 登録済は **CSV の登録が新しい順**（入れ間違いに気づいて直すときに、直前に登録したものを探しやすくするため）
- 至急の行は背景を薄い赤にし、納期の上に「至急」の印を出す
- 検索：受付No.・売り先・工事名で、読み込んだ行の中を絞り込む
- 「作業開始」：`start_cad_work()`。作業待ちのときだけの条件で 1 回の update で決めるため、同時に押しても 1 人に決まる。先にほかの人が始めていたら「○○さんが先に作業を始めていました」と出す。担当・開始日時はほかの人の画面にも Realtime で反映される
- 「作業開始を取り消す」（作業中の行の右のパネル）：`cancel_cad_work()`。作業待ちに戻し、担当と開始日時を空にする（押し間違い・担当の交代）。担当以外の人もできる。確認のダイアログを出す（担当がほかの人なら、その名前も出す）
- **CSV の入れ忘れに気づけるようにする**：作業中の行に、作業を始めてからの経過時間（「3時間20分」「1日4時間」）を出す。`CAD_LONG_RUNNING_HOURS`（`lib/intake/constants.ts`。初期値 24 時間）以上たった行は、背景をオレンジ系にし、右のパネルに「CSV を入れてください」の案内を出す。経過は 1 分ごとに進める。判定は `lib/intake/cad-elapsed.ts`
- 右のパネル：状態・アイトレ・先寸あり（同じ受付に起票前の先寸の加工区分がある）・至急の印、受付No.・売り先、工事名・納期（日付・曜日・配達）・加工場所・担当（開始日時・経過）、この加工区分の図面データ（「開く」、2 件以上なら「すべて図面ソフトで開く」）、注文書 PDF（新しいタブ）、**CSV のドロップ枠**
- CSV を入れられるのは **作業中と CSV 登録済の行だけ**（作業開始 → 部品作成 → CSV の出力の流れのため）。作業待ちの行では枠の代わりに「『作業開始』を押してから CSV を入れます」と出す。入れられるのは CSV だけ（1 ファイル 50MB まで）。複数入れられる
- CSV を登録：ブラウザが Storage に置いてから `add_cad_csv()` で `intake_files`（kind=`csv`）の行を作る → 今あるトリガー `intake_files_after_insert` で、作業中のアイトレを `ready`（受注登録待ち）にする。行を作れなかったら置いた実物を消す
- CSV の直し方（CSV 登録済のタブで行を選ぶ）
  - 中身が違った：同じ名前で入れ直すと差し替える（同じ加工区分の中で同じ名前は 1 つだけ）。名前が違うなら × で外して入れ直す
  - 足りなかった：追加で入れる
  - 別の受付に入れた：× で外す（`remove_cad_csv()`。論理削除して Storage の実物を消す）。CSV が 0 件になったら作業中に戻る（担当と最初の開始日時は残る）。担当以外の人も外せる。確認のダイアログを出す
  - 外せるのは CSV 登録済（起票前）の間だけ。起票完了の後は直さない。受注が加工区分を参照するようになったら（PR 9）、受注のある加工区分では外せないようにする
- CSV の中身を明細に取り込む処理は受注システム側の機能（今回は保存のみ）
- 右下に「ネスティング後のデータと用紙は、今まで通り現場に渡します」と案内する
- サイドメニューの「CAD」を押せるようにし、作業待ち・作業中の件数のバッジを出す（事務・管理者だけ。**ログイン中のユーザーの営業所の分**。管理者と営業所が空のユーザーは全部の営業所。`lib/intake/queue.ts` の `countScopeSiteId`。加工区分・受付の変更を Realtime で受け取って数え直す。`lib/intake/use-active-cad-count.ts`）
- 一覧は加工区分・受付の変更を Realtime で受け取って読み直す（ほかの人の作業開始・CSV の登録、振り分け完了で増えた行）
- 担当と、受付待ちの「対応中」の表示の違い：対応中は二重登録を防ぐための一時的な印（30 分で切れ、画面を閉じると外れる）。CAD の担当は誰が作業したかの記録で、期限はなく、CSV 登録済の後も残る

### S-06b 受注登録待ちに追加（モーダル）

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| 受付No. | ○ | 入力すると受付の情報と登録済みの受注を表示。見つからなければエラー |
| 追加の理由 | ○ | 振り分けの見落とし（`oversight`）／口頭での追加注文（`verbal`）／その他（`other`） |
| 区分 | ○ | 先寸（→ `ready`）／アイトレ（→ `cad_waiting`、CAD へ） |
| メモ | 「その他」のとき ○ | 追加の理由の詳細（200 文字まで。`work_units.note`） |
| 図面・注文書 | | PDF・DXF 複数可（kind=`added`） |

- 受付No. は Enter か「呼び出す」で呼び出す（`lib/intake/intake-no.ts` で正規化）。売り先・工事名・納期と、その受付の今の区分（区分・作られ方・状態）を出す。受注が受付につながる PR 9 からは、登録済みの受注（受注No.・部材区分）も出す
- 追加できるのは振り分け完了・完了の受付だけ。受付登録済（振り分け前）なら、呼び出した時点で「振り分けがまだ終わっていません」と出し、振り分けの画面へのリンクを出す。見つからない受付No. はエラー
- 「追加する」：ファイルを Storage に置いてから `add_work_unit_with_files()` で、区分とファイルの行（kind=`added`）を 1 つの transaction で作る。作れなかったら置いた実物を消す。受付が `closed` なら `dispatched` に戻す。一部のファイルを置けなかったときは、区分はできているため、どのファイルかを出して「閉じる」で一覧に戻る
- 区分が先寸なら受注登録待ちに並び、アイトレなら CAD の作業待ちに入る（CSV が登録されると受注登録待ちに並ぶ）。どちらも一覧の上に結果を知らせる
- 画面イメージ「06b」との違い：「登録済み」の受注の代わりに、PR 9 までは今の区分を出す。案内の枝番の例（26-1003-3）は、枝番の採番が PR 9 のため出さない。メモの欄を足す。図面・注文書は任意（ファイルがなくても追加できる）
- 実装：`components/order-queue/add-work-unit-dialog.tsx`、状態と追加の流れは `lib/intake/use-add-work-unit.ts`、選択肢と入力の確かめは `lib/intake/add-work-unit-form.ts`

サイドメニューは初期状態で閉じる（幅 64px）。

- 入口：受注登録待ちの一覧（S-06a）の行からだけ開く。`/orders/new` を `?unit=` なしで開いたとき・区分が見つからないとき・受注登録待ちでない（起票完了済みなど）ときは、受注登録待ちの一覧への案内だけを出し、新規の登録はさせない（受注は必ず受付を通すため）
- 上部：受付No.（一覧で選んだ受付、区分の印、追加の理由、至急、受付の担当者）、受注No.（**保存時に採番**。画面には「次の枝番」＝受付の `last_branch` + 1 を表示。ほかの人が先に登録すると、本当の枝番は表示より大きくなる）、この受付の登録済みの受注（受注No.・部材区分）
- 入力欄は「受注情報の入力欄」（上記）に、担当者（自社。社員No.、初期値はログイン中のユーザー）と至急（0 通常 / 1 至急。初期値は受付の至急）を足したもの。至急は受注にも持つ（`orders.is_urgent`。現場で優先して加工してもらうため）
- 受付から自動で入った値（売り先・客先担当・入れ先・工事名・納期・配達・加工場所・至急）は、欄の枠を薄い青にし、項目名の横に「受付の値」と出す。手で直した欄は通常の見た目に戻す（`lib/order-entry/intake-defaults.ts` の `isFromIntake`）。受付で空だった欄は、いつもの初期値のまま通常の見た目にする
- 納期の初期値：受付に日付があれば「1 確定」＋その日付、なければ「3 後報」。受付で「2 仮納期」「4 最短出荷」を選んでいれば、その種別のまま（`orderDueDateDefault`）
- 入れ先：初期値は受付の入れ先の 1 件目（なければ 0 売り先と同じ）。「/」の一覧の先頭に受付の入れ先を「受付 1｜名前」の形で並べ、その下に納入先マスタを並べる（先頭に出したものはマスタの並びから外す）
- 部材区分：0 無分類（初期値）/ 1 DF / 2 GPL / 3 BH / 4 SPL。**4 SPL を選ぶと、スプライス専用の受注になる**（継手番号・ショットの欄を 1 行目に表示する。本体の screen-design.md「スプライス専用の受注」）
- 加工場所：変更すると受付の加工場所も更新する（`create_order` の中で。変更の履歴はトリガーが残す）。この受付の残りの加工区分は変更先の受注登録待ちに移る。この画面で登録する受注は変更先の加工場所で保存する（＝変更先の出荷待ちに入る）。変更したときは、その旨の案内を欄の下に表示する
- 納期を変えても、受付の納期は書き換えない
- 左：注文書のパネル（中身は DocumentViewer）。注文書のタブは受付の注文書 PDF、図面データのタブは **この加工区分のファイルだけ**（振り分けた図面・追加分・CAD の CSV）を表示する
- 「受注情報を確定して次へ」→ S-06d。必須（売り先）が空なら、エラーを表示して進まない
- 処理区分 1 変更・2 削除：受注No. を入力して呼び出す。1 変更は受注情報を直して S-06d へ進み、明細も直せる。2 削除は確認のうえ論理削除する（出荷実績があれば削除しない）。受注登録待ちの一覧の「受注No. で呼び出す（変更・削除）」か、処理区分の欄で 1・2 を打って、受注No. を打つ画面（`/orders/edit`）から始める（PR 9b。本体の screen-design.md「受注の削除・修正」）
- 実装：`app/(main)/orders/new/page.tsx`・`actions.ts`、受付と区分の読み込みは `lib/intake/load-order-intake-source.ts`、初期値・入れ先の候補・薄い青の判定は `lib/order-entry/intake-defaults.ts`、入力欄は `components/order-entry/header/order-header.tsx`（薄い青は `form-item.tsx`、至急の欄は受付登録と共通の `components/intake/register/urgent-field.tsx`）

## 通知（画面側）

- 自分の部署の `notifications` の INSERT を Realtime で購読する（購読の条件 `dept=eq.{部署}`。RLS でも自分の部署の行しか届かない）。部署が空のユーザーは購読しない（ベルはいつも 0 件）
- 届いたら右上にトースト（5 秒。マウスを乗せている間は消えない。× で閉じられる。同時に 3 件まで）、ベルに未読数、メニューの件数を更新する（メニューの件数のバッジは、それぞれの画面を作る PR で出す。受付登録の項目の受付待ちの件数は PR 5 で出した。受付の変更を Realtime で受け取って数え直す。`lib/intake/use-waiting-intake-count.ts`）
- ベルの未読数は 10 件以上なら「9+」。0 件なら出さない
- ベルを開くと未読の一覧（新しい順に 20 件。題名・本文・何分前か。入りきらない分は「ほか○件」）。押した通知は既読（`notification_reads`）にし、受付の新着なら受付待ち一覧でその行を選んだ状態で開く（`lib/notifications/link.ts`。トーストを押したときも同じ）。「すべて既読にする」でまとめて既読にする
- トーストを閉じても、通知は未読のまま（ベルの一覧に残る）
- 最初の未読の一覧は共通レイアウト（サーバー側）で読み、その後の新着は Realtime で足す
- 実装：`components/notifications/`（Provider・トースト・一覧）、`components/layout/notification-bell.tsx`、`lib/notifications/`（状態の更新・Realtime の購読・未読の読み込み）、`app/actions/notifications.ts`（既読にする）、ブラウザ用の Supabase クライアント `lib/supabase-browser.ts`
- 確認の手順：seed 008（`supabase/seed/008_notification_demo.sql`）を SQL Editor で実行すると、シャーリング部への通知が 1 件できる

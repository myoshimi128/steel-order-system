## 共通の部品

### DocumentViewer（S-04c・S-06c の左側）

タブ「注文書（PDF）」「図面データ（件数）」を持つ。

- 注文書：PDF を画面内に表示する（ページ送り・拡大・別ウィンドウ）
- 図面データ：その画面で扱う区分の DXF の一覧と「開く」「すべて開く」

受注登録（S-06c・S-06d）では、DocumentViewer を「注文書のパネル」として 2 つの画面の左に置く。幅をドラッグで変えられ、F2 で開閉できる（本体の screen-design.md「受注登録画面」の「注文書のパネル」）。事務所の PC は画面 1 枚のため、別ウィンドウではなく画面の中で表示する。

### DXF を開く

- 署名付き URL を `download` 指定で発行し、ブラウザでダウンロードする → パソコンの関連付けで図面ソフトが起動する
- 初回だけ、ブラウザで「この種類のファイルを常に開く」を設定する（ヘルプの文言を画面に表示する）
- ダウンロードするときのファイル名：`{受付No.}_{区分}_{元のファイル名}`（`lib/intake/file-name.ts`）

### 受注情報の入力欄（S-04c・S-06c で共通）

受付登録（S-04c）と受注情報（S-06c）は、同じ入力欄のコンポーネントを使い回す。項目と初期値は basic-design.md「受注情報（受付と受注で共通の入力）」を参照。入力は本体の「入力方式」（番号の欄＋名称、Enter で次へ、「/」または End で一覧）に従う。

| 行 | 受付登録（S-04c） | 受注情報（S-06c） |
| --- | --- | --- |
| 1 | 処理区分・受付No.・受付日・担当者 | 処理区分・受注No.・部材区分（SPL のときは継手番号・ショット）・受注日・担当者 |
| 2 | 売り先・客先担当 | 売り先・客先担当 |
| 3 | 入れ先（複数。「＋入れ先を追加」で行を増やす） | 入れ先（1 件） |
| 4 | 工事名 | 工事名 |
| 5 | 納期（種別＋日付）・配達 | 納期（種別＋日付）・配達 |
| 6 | 加工場所・至急 | 加工場所 |

- Enter の順路は左上から右下へ。最後の欄で Enter を押すと、画面の確定ボタン（「受付No. を発行して登録」「受注情報を確定して次へ」）へ移る
- 受付No.・受注No. の欄では「-」をハイフンとして入力する（テンキーの「-」でハイフンを打てるようにするため）。入力は `lib/intake/intake-no.ts` で正規化する（`26-1003` / `261003` / `26 1003` → `26-1003`、`26-1` → `26-0001`。ハイフンなしは連番 4 桁以上のときだけ受け付ける）
- 担当者は社員No. で入力する。「/」の一覧から選ぶこともできる。初期値はログイン中のユーザー
- 加工場所は番号の欄（1 本社 / 2 A営業所 / 3 B営業所）。初期値が必ず入るため、番号 0 は使わない
- 受付から自動で入った値は薄い青で表示し、手で直した欄は通常の色に戻す（受付の値と違うことが分かるようにする）

**入れ先（受付）**

- 行ごとに番号の欄を 1 つ置き、納入先マスタのコードを打つ（0 は売り先と同じ）。初期状態は「0 売り先と同じ」の 1 行
- 「＋入れ先を追加」で行を増やす。行ごとに削除できる。並び順を保存する
- 同じ納入先を 2 行入れることはできない

**入れ先（受注）**

- 番号の欄は 1 つ。打つ数字は納入先マスタのコード（0 は売り先と同じ）
- 初期値は受付の入れ先の 1 件目
- 「/」の一覧の先頭に、受付に登録した入れ先を「受付 1」「受付 2」…の印を付けて並べ、その下に納入先マスタの検索を出す。↑↓ と Enter で選ぶ
- 受付の入れ先が 1 件なら、Enter だけで進める

## 画面

### S-00 ログイン

- 社員No.（必須）とパスワード（必須）を入力する
- 社員No. から、決まった形のメールアドレスを作って Supabase Auth に渡す（本体の basic-design.md「権限設計」）
- 失敗したときは「社員No. またはパスワードが正しくありません」と表示する（どちらが違うかは区別しない。社員No. の形の違い・無効のユーザーも同じ文）。空のまま押したときは「社員No. とパスワードを入力してください」。エラーのあとも社員No. の欄の値は残す
- 社員No. は小文字・全角で打ってもよい（大文字・半角にそろえる）
- 見た目は画面イメージ「00 ログイン」に合わせる：上にネイビーの帯、地は薄い格子柄。中央にロゴ・システム名・英字の副題、その下に上の縁がネイビーのカード（見出し「ログイン」、社員No.・パスワードの欄に必須の赤い＊、パスワードの表示の切り替え、ネイビーのログインのボタン）。カードの下に注意書き、画面の下端に著作権の表示と問い合わせ先
- 実装：`app/login/page.tsx`、`components/login/`（ロゴ・フォーム・項目名・パスワードの欄・下端の帯）、`app/actions/auth.ts`（`login`）

### S-01 ホーム

- 上部：あいさつ（「おはようございます、○○さん」）と今日の日付（例：2026年10月19日（月））。あいさつは日本時間の時刻で変える（5〜10 時台「おはようございます」、11〜16 時台「こんにちは」、それ以外「こんばんは」。`lib/home/greeting.ts`）
- 左：社内連絡。**Phase 1 は枠と見出しだけを出し、「社内連絡は準備中です」と表示する**。お知らせの登録・一覧は Phase 2（F-24）。画面イメージのお知らせはサンプルのため、コードには持たない
- 右：目安納期。加工部・シャーリング部のカード（工程・日数・混雑度の印・部署メッセージ・更新日時と更新者）。凡例を表示する
- 部署メッセージは、表示期限（`expires_on`）の日まで表示し、次の日から表示しない。期限が空なら表示し続ける
- 混雑度が「要相談」の工程と、日数がまだ入っていない工程は、日数の代わりに「—」を表示する
- 混雑度の印の色：通常は白地に枠、やや混雑は薄いネイビー、混雑はネイビー、要相談は赤
- 更新日時と更新者は、その部署の最新の更新履歴（`lead_time_history`）から出す
- 画面イメージ「01 メインメニュー」との違い：社内連絡の中身と「すべて見る」は出さない。ベルは赤い点ではなく未読の数を出す
- 実装：`app/(main)/page.tsx`、`components/home/`、カード・混雑度の印・凡例は納期連絡のプレビューと共通（`components/lead-time/`）。読み込みは `lib/lead-time/load-lead-times.ts`

### S-02 部署ホーム（シャーリング部）

- 件数のカード：受付待ち／受注登録待ち／本日納期／加工図面未発行（加工図面は将来。今は 0 または非表示）
- 部署内連絡・部署タスクは **Phase 2**（画面は表示のみ）
- ボタン：受付登録へ・受注登録へ

### S-03 納期連絡

- 工程ごとに：目安日数（営業日・整数 0〜99）、混雑度（通常／やや混雑／混雑／要相談の 4 択）、補足（ホームには出さない）。工程の追加・並べ替え（↑↓のボタン）
  - 「要相談」のときは日数を入れない（空で保存し、ホームでは「—」）。それ以外は日数が必須
  - 追加した工程は、名前を入れる。同じ部署に同じ名前の工程は作れない。公開する前なら × で追加を取り消せる
  - **工程の削除・非表示はできない**（工程がなくなることは基本的にないため）。工程の削除・非表示は、必要になったら追加する。既存の工程の名前も変えない
- 部署メッセージ（文章。200 文字まで）と表示期限（日付。受注登録と同じ打ち方の欄で、月日 4 桁で入れられる）。メッセージを空にすると、表示期限も空にする
- 右：ホームでの表示のプレビュー（入力中の内容がすぐ反映される）、更新履歴（新しい順に 10 件）
- 「ホームに公開」で保存する（保存＝公開。下書きはなし）。保存のたびに `lead_time_history` に要約を 1 行残す（例：「レーザー 3→2営業日、プラズマを「やや混雑」に変更、メッセージを更新」。`lib/lead-time/summary.ts`）。何も変えていなければ「変更がありません」として公開しない
- **画面を開いた後にほかの人が先に公開していたら、上書きせずにエラーにする**（「ほかの人が先に公開しました。…画面を開き直して…」）。気づかずにほかの人の変更を消してしまうのを防ぐため。開いた時点の最新の更新履歴と、公開する時点の最新の更新履歴を比べる
- 「元に戻す」で、最後に公開した状態に戻す
- 編集できるのは事務・管理者（`publish_lead_times` と RLS でも強制する）。部署では制限しない（権限はロールで決める）。現場のユーザーには同じ画面を「閲覧のみ」で出す（入力できず、ボタンを出さない）
- 加工部の納期連絡も同じ画面を部署の切り替え（シャーリング部 / 加工部のタブ。`?dept=processing`）で使う。入り口はシャーリング部のメニューの「納期連絡」だけ（Q-7 の決定）。公開していない入力があるときは、切り替える前に確かめる
- 画面イメージ「03 納期連絡」との違い：上に部署の切り替えを足す。サイドメニューの部署の枠の人数（「本社 15名」）と、業務メニューの件数のバッジは出さない。表示期限の欄にカレンダーのアイコンは付けない
- 実装：`app/(main)/shearing/lead-time/page.tsx`・`actions.ts`（`publishLeadTimes`）、`components/lead-time-editor/`、入力の状態は `lib/lead-time/use-lead-time-editor.ts`、入力の確認は `lib/lead-time/draft.ts`

│ │ NEW  受信日時  経路  差出人  件名  添付              │ │ 件名・本文          │ │
│ │ …                                                  │ │ 添付ファイルの一覧   │ │
│ │                                                    │ │ [対象外][見積・ミルシート]│ │
│ └────────────────────────────────┘ │ [この内容で受付登録 →]│ │
│                                                         └──────────┘ │

- タブ：受付待ち／受付登録済（＝振り分け待ち）／見積・ミルシート／対象外

- 右下：対象外／見積・ミルシート／**この内容で受付登録** → S-04c
- 開いた時点で `handling_by` を自分にする。他人が対応中の行は「○○さんが対応中」と表示する（30 分で自動解除）
- 「受付登録済」タブの行 → S-04d 振り分けへ
- 一覧の下に「電話注文など、メール・FAX 以外の受付は『手動で受付を追加』から登録できます」と案内する
- 新着の通知が届くと、右上にトーストを表示し、一覧に行が追加される

### S-04b 手動で受付を追加（モーダル）

- 経路（口頭・電話／来社／メール（転送漏れ）／その他）、受付日時（初期値：今）、注文書（PDF・DXF、任意・複数）、メモ

### S-04c 受付登録

```

│ ┌ DocumentViewer ─────────┐ ┌ 受注情報の入力欄（受付） ──────────────┐ │

│ │                          │ │ 売り先 / 客先担当                       │ │
│ │  注文書 PDF の表示         │ │ 入れ先 1, 2 …  [＋入れ先を追加]          │ │

```

- 入力欄は「受注情報の入力欄」（上記）。必須は売り先だけ
- 至急はチェック（赤）。受注登録待ち・CAD の先頭に並ぶ
- 「受付No. を発行して登録」：`register_intake()` を呼ぶ（受付No. の採番・`registered` にする・登録者の記録）→ S-04d へ

- 左の DocumentViewer で、注文書と添付の DXF を確認できる
- 処理区分 1 変更：受付No. を入力して呼び出し、入力欄を直して「変更を保存」。登録済みの受注は書き換えない
- 処理区分 2 削除：受付No. を入力して呼び出し、確認のうえ論理削除する。受注が 1 件でもあればエラーを表示して削除しない

### S-04d 振り分け

```
┌ 振り分け  26-1003  A製作所  ○○ポンプ設備工事（その2）  納期 10/03 ────────────┐
│ ┌ 元データ（メール添付）  振り分け完了で自動削除 ┐ ┌ 振り分け ───────────────────┐ │
│ │ [すべて図面ソフトで開く]                     │ │ ┌ 先寸 3ファイル ┐ ┌ アイトレ 2ファイル ┐ │ │
│ │ 組立_全部品.dxf  複数部品  分割して保存済 [開く] │ │ │ …            │ │ …               │ │ │
│ │ PL9-297×1530.dxf          → 先寸   [開く] │ │ │ ここにドロップ  │ │ ここにドロップ    │ │ │
│ │ PL12-340×438.dxf          未振り分け [開く] │ │ │ →受注登録待ちへ │ │ →CAD（部品作成待ち）│ │ │
│ │ （操作の案内）                             │ │ └────────┘ └─────────┘ │ │
│ └──────────────────────┘ │ 未振り分けの元データが 1 件あります [一時保存][振り分け完了 →] │ │
│                                                 └─────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- 左：元データの一覧（各行に「開く」、状態：→先寸／→アイトレ／分割して保存済／未振り分け）、「すべて図面ソフトで開く」
- 右：**先寸の枠** と **アイトレの枠**。複数のファイルをドロップできる。元データの行を枠へドラッグしてもよい（＝その元データをそのまま複製して振り分け済みにする）
  - 1 つの DXF に複数の部品 → 図面ソフトで先寸の部品だけ残して「名前を付けて保存」→ 先寸の枠へ。アイトレも同様
  - 1 部品ずつの DXF → そのまま枠へドラッグ
  - 同じ枠に同じ名前のファイルを入れたら差し替え
- 元データの状態の表示：元データと同じ名前のファイルが枠にあれば「→先寸／→アイトレ」。分割したファイルとの対応は、人が「分割して保存済」にチェックする
- 「振り分け完了」：`complete_split()` を呼ぶ
  - 先寸の枠にファイルがあれば `sakisun`（ready）、アイトレの枠にあれば `aitore`（cad_waiting）の加工区分を作り、枠のファイルをそれぞれに紐付ける
  - **図面が 1 つもない注文（FAX・口頭）**：ボタン「図面なしで 先寸として登録」「図面なしで アイトレとして登録」を表示する
  - 元データ（kind=`original`）を論理削除し、アプリが Storage から実ファイルを削除する
  - 未振り分けの元データがある場合は確認のダイアログ（「削除されます。よろしいですか」）を出す
- 「一時保存」：枠の状態だけを保存する（status は registered のまま）
- 左下に操作の案内を表示する（複数部品の DXF は図面ソフトで分けて保存、1 部品ずつの DXF はそのままドラッグ、要変換のファイルは DXF に変換してから）

### S-05 CAD

- タブ：作業待ち・作業中／CSV 登録済
- 列：至急・納期・受付No.・売り先・工事名・加工場所・図面（DXF）・担当・状態
- 並び順は「並び順」（後述）のとおり
- 「作業開始」：`cad_working`・担当者・開始日時を記録する（他の人の画面にも反映される）
- 右のパネル：受付の情報、アイトレの DXF「すべて図面ソフトで開く」、注文書 PDF、**CSV のドロップ枠**

- 右下に「ネスティング後のデータと用紙は、今まで通り現場に渡します」と案内する

### S-06a 受注登録待ち一覧

- 上部に 3 段階の進み具合（①受注登録待ち → ②受注情報 → ③注文内容）を表示する
- タブ：加工場所（本社／A営業所／B営業所、件数つき）
- 対象：`work_units.status='ready'`。列：至急・納期・受付No.・売り先・工事名・区分（先寸／アイトレ＋CSV 登録済）・追加（見落とし追加／口頭）・受付の担当者
- 至急の行は背景を薄い赤にする
- 並び順は「並び順」（後述）のとおり
- 行を選ぶ → S-06c（処理区分 0 新規）
- 右上「受注登録待ちに追加」→ S-06b
- 一覧の下に「先寸は振り分け完了ですぐに、アイトレは CAD で CSV が登録されるとここに並びます」と案内する

### S-06b 受注登録待ちに追加（モーダル）

| 項目 | 必須 | 備考 |
| --- | --- | --- |

### S-06c 受注情報

```
┌ 受注登録    ✓受注登録待ち ─ ②受注情報 ─ ③注文内容 ──────────────────────┐
│ ┌ DocumentViewer ─────────┐ ┌ 受注情報の入力欄（受注） ──────────────┐ │
│ │ [注文書(PDF)] [図面データ 3]  │ │ 受付No. 26-1003 [先寸] 受付: 担当者名       │ │
│ │ この受注の図面 [先寸]        │ │ 受注No. 26-1003-2（登録時に採番）           │ │
│ │ 26-1003_先寸.dxf  [開く]     │ │   この受付の受注: 26-1003-1 GPL 登録済       │ │
│ │ …                          │ │ 処理区分 / 部材区分 / 受注日 / 担当者          │ │
│ │                            │ │ 売り先 / 客先担当 / 入れ先                   │ │
│ │                            │ │ 工事名 / 納期 / 配達 / 加工場所               │ │
│ └──────────────┘ │ [クリア] [受注情報を確定して次へ →]          │ │
│                                └──────────────────────┘ │
└────────────────────────────────────────────────┘
```

サイドメニューは初期状態で閉じる（幅 64px）。

- 上部：受付No.（一覧で選んだ受付、区分の印、受付の担当者）、受注No.（**保存時に採番**。画面には「次の枝番」を表示）、この受付の登録済みの受注（受注No.・部材区分）
- 入力欄は「受注情報の入力欄」（上記）。受付から自動で入った値は薄い青で表示する
- 部材区分：0 無分類（初期値）/ 1 DF / 2 GPL / 3 BH / 4 SPL。**4 SPL を選ぶと、スプライス専用の受注になる**（継手番号・ショットの欄を 1 行目に表示する。本体の screen-design.md「スプライス専用の受注」）
- 加工場所：変更すると受付の加工場所も更新する（変更の履歴を残す）。この受付の残りの加工区分は変更先の受注登録待ちに移る。この画面で登録する受注は変更先の加工場所で保存する（＝変更先の出荷待ちに入る）。変更したときは、その旨の案内を欄の下に表示する
- 納期を変えても、受付の納期は書き換えない
- 左：DocumentViewer。図面データのタブは **この加工区分のファイルだけ** を表示する
- 「受注情報を確定して次へ」→ S-06d。必須（売り先）が空なら、エラーを表示して進まない
- 処理区分 1 変更・2 削除：受注No. を入力して呼び出す。1 変更は受注情報を直して S-06d へ進み、明細も直せる。2 削除は確認のうえ論理削除する（出荷実績があれば削除しない）

### S-06d 注文内容

本体の受注登録画面の ② 注文内容（明細の表は 1 件 1 行）を使う（本体の screen-design.md「受注登録画面」）。明細の表の下にスタンプ・フリーコメントの帯があり、この画面で登録する。

- 上部に受注情報の要約（受注No.・部材区分・売り先・納期・入れ先）と「受注情報に戻る」を表示する。戻っても入力した明細は消さない
- 左の注文書のパネル（DocumentViewer）に、受付に保存された注文書 PDF・この加工区分の図面データを表示する。パネルの幅はドラッグで変えられ、F2 で開閉できる
- 明細の列・切断・区分の番号・キー操作は本体の設計に従う。この画面イメージの英字のコード（L1・K2 など）と、行挿入・行削除以外のキー（Enter・End）の案内は参考とする
- 「登録して現場用伝票を印刷」で保存するとき：
  1. `create_order` の中で枝番を採番し、受注No. を確定する（保存と同じ transaction）
  2. 受注に `intake_id`・`work_unit_id`・`branch_no`・`member_class`・`site_id` を保存する
- 登録後に選ぶ：「同じ受付から続けて登録」（S-06c に戻る。受付の情報はそのまま入れ直す）／「**この区分の起票を完了**」（`complete_work_unit()` → 一覧から消える）

### S-07 マスタ管理

- 既存のマスタ管理の画面を、共通レイアウトに合わせた見た目（左にマスタの分類の一覧、中央に一覧、右に編集のパネル）に寄せる。**データの構造は既存のもの** を使う

## 並び順（`lib/intake/sort.ts`）

- 受注登録待ち・CAD：①至急 ②受付の納期の日付が早い順 ③納期の日付なし ④受付登録日時が古い順
- 受付待ち：受信日時が新しい順

## 通知（画面側）

- 自分の部署の `notifications` の INSERT を Realtime で購読する（購読の条件 `dept=eq.{部署}`。RLS でも自分の部署の行しか届かない）。部署が空のユーザーは購読しない（ベルはいつも 0 件）
- 届いたら右上にトースト（5 秒。マウスを乗せている間は消えない。× で閉じられる。同時に 3 件まで）、ベルに未読数、メニューの件数を更新する（メニューの件数のバッジは、それぞれの画面を作る PR で出す）
- ベルの未読数は 10 件以上なら「9+」。0 件なら出さない
- ベルを開くと未読の一覧（新しい順に 20 件。題名・本文・何分前か。入りきらない分は「ほか○件」）。押した通知は既読（`notification_reads`）にする。「すべて既読にする」でまとめて既読にする。押したときの移動先（受付待ち一覧）は PR 5 で足す
- トーストを閉じても、通知は未読のまま（ベルの一覧に残る）
- 最初の未読の一覧は共通レイアウト（サーバー側）で読み、その後の新着は Realtime で足す
- 実装：`components/notifications/`（Provider・トースト・一覧）、`components/layout/notification-bell.tsx`、`lib/notifications/`（状態の更新・Realtime の購読・未読の読み込み）、`app/actions/notifications.ts`（既読にする）、ブラウザ用の Supabase クライアント `lib/supabase-browser.ts`
- 確認の手順：seed 008（`supabase/seed/008_notification_demo.sql`）を SQL Editor で実行すると、シャーリング部への通知が 1 件できる

# 画面設計書

## 共通方針

### 対象環境

事務所の既存 PC で使用する。画面解像度は 1280 × 1024 を前提とし、モバイル・タブレット対応は行わない。ブラウザの UI 領域を除いた実質的な表示領域はおよそ 1280 × 900 として設計する。

利用者が限定され、使用する端末も固定されているため、レスポンシブ対応に工数を割かず、その解像度で最も使いやすい形に最適化する。

### レイアウトの考え方

現行の紙伝票の書式を画面上で再現し、伝票に直接打ち込む形式とする。

既存の業務フォーマットをそのままインターフェースとすることで、次の効果を狙う。

- 入力中に出力物の完成形が見えるため、印刷して初めて気づく誤りが減る
- 現場が受け取る伝票の見た目が変わらず、従来どおり扱える
- 印刷した伝票と画面を照合する作業が速い
- 新しい操作を覚える必要がなく、導入時の教育コストが低い

横スクロールは発生させない。伝票は横長だが、表示領域に収まるよう全体を縮尺調整する（CSS の `transform: scale()` などを用い、レイアウトを崩さずに収める）。縮小しすぎると入力しづらくなるため、実際の画面で確認しながら調整する。

## 受注登録画面

画面デザイン:

- 通常の受注: `docs/images/受注登録（通常）@1x.png`
- スプライス専用の受注: `docs/images/受注登録（スプライス専用）@1x.png`

### 用語：仕入単価

この画面で自動計算する単価・金額は、すべて **仕入単価・仕入金額** である（価格マスタから求める自社の仕入値）。売上単価は営業が決めるものであり、MVP では扱わない（後述「受注入力で扱わないもの」）。

### 全体構成

画面を上から次の順に並べる。

```
┌─────────────────────────────────────────┐
│ ヘッダー（3 行）                  ← 固定表示  │
├─────────────────────────────────────────┤
│ 明細                                      │
│  材料の行（2 段）・加工の行（1 段）  ← この部分だけスクロール │
├─────────────────────────────────────────┤
│ 合計（重量・仕入金額・単価未定の件数）          │
│ キー操作の案内                              │
│ 補助エリア（注意事項 / スタンプ / フリーコメント） │
│ キャンセル / 登録して現場用伝票を印刷           │
└─────────────────────────────────────────┘
```

1 件の受注で明細が 100 行を超えることもあるため、ヘッダーは固定表示とし、明細の部分だけをスクロールさせる。入力中に得意先や納期を見失わないようにするためである。

自動計算の欄はグレーで表示し、入力する欄と区別する。

### 入力方式

明細が多い受注でも手早く入力できるよう、**テンキーだけで入力を完結できるコード入力** とする。

- 選択する項目はすべて「番号の欄 ＋ 名称表示」とする。番号を打つと、右側に名称が表示される
- 初期値がある項目は Enter だけで次の項目へ進める
- 番号が分からないときは「/」で選択肢の一覧を開き、番号を打つか ↑↓ で選んで Enter で確定する

**検索付きの一覧（売り先・入れ先）**

売り先・入れ先は件数が多く番号を覚えていないことがあるため、「/」で開く一覧に検索の欄を付ける。選択肢の少ない欄（処理区分・納期種別・配達など）は、検索なしの一覧のままとする。

- 一覧を開くと検索の欄にフォーカスが移り、ふりがな・名前のどちらでも部分一致で検索できる
- 打つたびに候補が絞られる。↑↓ で選んで Enter で、番号と名称が入り次の項目へ進む
- Esc で一覧を閉じ、番号の欄に戻る
- ひらがな／カタカナ、全角／半角、英字の大文字／小文字の違いは区別しない。空白は無視する（「株式会社 サンプル」を「株式会社サンプル」でも探せる）
- 日本語入力の変換中の Enter・↑↓ は変換の操作として扱い、候補の選択には使わない
- ふりがなは得意先・納入先マスタの `name_kana` を使う。ふりがなが未登録の行も名前で検索できる

検索の正規化と絞り込みは `lib/code-input/search.ts`、一覧の表示は共通部品 `CodeList`（検索の有無を切り替えられる）に実装している。

**キー操作（番号・寸法・数量の欄）**

| キー | 動作 |
| --- | --- |
| Enter | 次の項目へ進む（材料の行は数量の後、次の行へ進む） |
| Shift + Enter | 前の項目へ戻る |
| / | 選択肢の一覧を開く（一覧では番号か ↑↓ で選んで Enter、Esc で閉じる） |
| * | 直前の行を複写する |
| + | 加工の行を追加する |
| - | その行の摘要へ移動する |
| Ctrl + Delete | 行を削除する |
| Ctrl + Insert | 行を挿入する |

文字を入れる欄（工事名・加工内容・摘要など）では、`/` `*` `+` `-` は普通の文字として入力する。

摘要は Enter の順路に含めない（数量の後は次の行へ進む）。摘要を入力する行だけ、番号・寸法・数量の欄で「-」を押して移動する。

存在しない番号を入力した欄では、エラーを表示して次の項目へ進ませない。文字の欄では、日本語入力の変換を確定する Enter では次の項目へ進まない。

**日付の入力**

日付の欄（受注日・納期）も数字だけで入力する。

| 入力 | 解釈 |
| --- | --- |
| 4 桁（例: `1005`） | 今年の 10 月 5 日 |
| 8 桁（例: `20261005`） | 2026 年 10 月 5 日 |

入力した日付は `2026/10/05` の形で表示し直す。存在しない日付（2 月 30 日など）はエラーにして次の項目へ進ませない。「今年」は日本時間の今日の年とする。

キー割り当ては現行システムに合わせず、ブラウザの標準操作と衝突しないよう独自に設計した。画面下部にキー操作の案内を常に表示する。

**番号の一覧**

固定の選択肢の番号はアプリ側の定数で持つ。マスタで持つ選択肢の番号は、各マスタの番号の列（table-design.md 参照）で持つ。

| 項目 | 番号 | 持ち方 |
| --- | --- | --- |
| 処理区分 | 0 新規 / 1 変更 / 2 削除 | 定数 |
| スプライス | 0 通常（初期値）/ 1 スプライス | 定数 |
| 売り先・入れ先 | 得意先コード・納入先コード（数字のみ） | マスタ（`customers.code` / `delivery_destinations.code`） |
| 切断方法 | 1 シャーリング / 2 ガス / 3 レーザー / 4 プラズマ / 9 定尺 | 定数 |
| 区分 | 1 寸法切 / 2 アイトレ / 3 定尺 / 9 加工。ササラ・ベタ丸・ドーナツは特殊製品種別マスタの番号（例: ベタ丸 7） | 定数＋マスタ |
| 種類 | 0 普通板（初期値）/ 1 縞板 / 2 ボンデ / 3 ミガキ | マスタ（`plate_types`） |
| 材質 | マスタの番号（例: 1 SS400 … 9 TMCP385C） | マスタ（`materials`） |
| 製鋼法 | 1 電炉（初期値）/ 2 高炉 | 定数 |
| メーカー | 0 指定なし（初期値）。それ以外はメーカーコード | マスタ（`manufacturers.code`） |
| 加工方法 | マスタの番号（例: 11 キリ孔、14 ショット） | マスタ（`process_types`） |
| 加工の単位 | 1 個（初期値）/ 2 kg | 定数 |
| 納期種別 | 1 確定 / 2 仮納期 / 3 後報 / 4 最短出荷 | 定数 |
| 配達 | 0 宵積み / 2 2便 / 3 置場引取 / 4 営業配達 / 5 横持ち / 6 宅急便 / 9 フリー | マスタ（`delivery_methods`） |
| 定尺サイズ | 1 3x6 / 2 4x8 / 3 5x10 | 定数 |

特殊製品種別の番号は、区分の定数（1・2・3・9）と重ならない値にする。

### ヘッダー

3 行で構成する。Enter で左上から右下へ順に進む。

| 行 | 項目 |
| --- | --- |
| 1 行目 | 処理区分・受注 No.・スプライス（番号の欄）・受注日 |
| 2 行目 | 売り先・担当者・入れ先（売り先と入れ先は名称が長いため広く取る） |
| 3 行目 | 工事名（右端を担当者に揃える）・納期（種別＋日付）・配達 |

| 項目 | 保存先 | 補足 |
| --- | --- | --- |
| 処理区分 | —（画面の動作を切り替える） | 0 新規なら受注 No. は自動採番。1 変更・2 削除なら受注 No. を入力して既存の受注を呼び出す。削除は論理削除（後述） |
| 受注 No. | `orders.order_no` | 新規では「（自動採番）」と表示し入力不可 |
| スプライス | `orders.is_splice` | 番号の欄。0 通常（初期値）/ 1 スプライス。1 にするとスプライス専用の受注になる（後述） |
| 受注日 | `orders.order_date` | 登録日を初期値として自動設定し、必要な場合のみ変更する |
| 売り先（得意先） | `orders.customer_id` | 得意先コード（数字のみ）で入力する。選択すると注意事項の表示・指定スタンプのチェックが行われる |
| 担当者（客先担当） | `orders.customer_contact` | 得意先側の窓口担当者。受注ごとに異なるため自由入力 |
| 入れ先（納入先） | `orders.delivery_destination_id` | 納入先コード（数字のみ）で入力する |
| 工事名 | `orders.project_name` | 自由入力 |
| 納期（種別＋日付） | `orders.due_date_type` / `orders.due_date` | 種別が 1 確定・2 仮納期のときのみ日付を入力する |
| 配達 | `orders.delivery_method_id` / `orders.delivery_method_note` | 9 フリーのときは文字を入力する欄を表示する |

受注番号・起案者は自動で設定する。仕入先はヘッダーに置かない。

売り先・入れ先のコードはテンキーで入力できるよう数字のみとする（画面デザインの画像では `C001` `D001` と表示しているが、実際のコードは数字のみ）。

### 明細

明細は材料の行と、それに紐づく加工の行で構成される。加工指示書では加工が重量ゼロの別行として印字されているため、画面上も同様に行として並べる。データ構造としては材料が親（`order_items`）、加工が子（`order_item_processes`）となる。

#### 材料の行（2 段）

1 行を 2 段に分け、1 つの欄に 2 つの値を上下に重ねる。

| 欄 | 上段 | 下段 |
| --- | --- | --- |
| No | 行番号 | |
| 切断方法／区分 | 切断方法 | 区分 |
| 種類／製鋼法 | 種類 | 製鋼法 |
| 材質／メーカー | 材質 | メーカー |
| 品名／寸法 | 品名（表示のみ） | 区分名と寸法の入力欄 |
| 数量／重量 | 数量 | 重量（自動） |
| 仕入単価／仕入金額 | 仕入単価（自動） | 仕入金額（自動） |
| 摘要 | 明細の摘要（行末で中身が見える入力欄） | |

入力順は「切断方法 → 区分 → 種類 → 材質 → 製鋼法 → メーカー → 寸法 → 数量」で、数量の後は次の行へ進む。

**品名／寸法の欄**

品名の欄を一番広く取る。

- 上段の品名は、種類（普通板以外）・材質・製鋼法・指定メーカーから組み立てて表示する（例: `SN490C 電炉`、`縞板 SS400 メーカーA`）。入力はしない
- 下段は区分名に続けて、最初に板厚、次に区分に応じた寸法を入力する（例: `寸法切 40 × 660 × 660`、`ベタ丸 9 × 直径 300`、`定尺 4.5 × 2 4x8`）

**切断方法と区分**

切断方法で「9 定尺」を選ぶと、区分も自動で「3 定尺」になり変更できなくなる。保存時は `cutting_method` を NULL にする（定尺売りは切断を伴わないため）。

区分は画面上は 1 つの番号の欄だが、裏側では定尺売り・切断区分・特殊製品に振り分けて保存する。

| 区分 | `cutting_type` | `special_product_type_id` | 寸法の入力欄（板厚の後） | 寸法の保存先 |
| --- | --- | --- | --- | --- |
| 1 寸法切 | 寸法切 | NULL | 縦 × 横 | `width` / `length` |
| 2 アイトレ | アイトレ | NULL | 縦 × 横 | `width` / `length` |
| 3 定尺 | NULL | NULL | 定尺サイズ（1 3x6 / 2 4x8 / 3 5x10） | `plate_size` |
| 9 加工 | — | — | 加工の行に切り替わる（後述） | — |
| ササラ（マスタの番号） | NULL | ササラ | 使用材の寸法（縦 × 横） | `width` / `length` |
| ベタ丸（マスタの番号） | NULL | ベタ丸 | 直径 | `outer_diameter` |
| ドーナツ（マスタの番号） | NULL | ドーナツ | 外径 × 内径 | `outer_diameter` / `inner_diameter` |

スプライスは通常の受注の区分の一覧に出さない。スプライスはスプライス専用の受注で扱う（後述）。

板厚は `products` から特定する商品に含まれるため、明細には直接保存しない。

**種類・材質・製鋼法**

種類の初期値は 0 普通板とする。材質の選択肢は、選んだ種類について商品マスタ（`products`）に登録されている組み合わせから絞り込む。現在の登録内容では次のようになる。

| 種類 | 材質の選択肢 |
| --- | --- |
| 普通板 | SS400、SM490A、SN400B など普通板として登録されている材質 |
| 縞板 | SS400 のみ |
| ボンデ・ミガキ | 材質なし（無規格） |

製鋼法の初期値は 1 電炉とする。ただし次の場合は製鋼法を「—」表示にして入力させず、`steel_making` を NULL で保存する。

- 区分が定尺のとき（定尺単価には高炉材加算がなく、製鋼法を使わないため）
- 種類が材質エキストラを適用しない種類のとき（`plate_types.applies_material_extra` が false。縞板・ボンデ・ミガキ）

**メーカー**

初期値は「0 指定なし」とし、客先から指定があった場合のみメーカーコードを入力する。

縞板のときは必須とし、選択肢は単位質量（`unit_weights`）が登録されているメーカーだけに絞る。縞板は単位質量がメーカーによって異なり、重量計算に必要なためである。

メーカーの選択時点では板厚が決まっていない（板厚は後の寸法欄で入力する）ため、メーカーの絞り込みは板厚を問わず「単位質量が 1 件でも登録されているメーカー」とする。メーカーと板厚のどちらかが変更されたら、その組み合わせに単位質量が登録されているかを確認し、なければエラーを出す（重量が計算できないため登録できない）。板厚を先に入力してから後でメーカーを変更した場合も、同じ確認を行う。

**取り扱いのない板厚**

種類・材質・形状（定尺 / 大板）と合わせて商品マスタに該当がない板厚の場合は、その行を強調表示し、行の下に「14mm は取り扱いがありません。商品マスタに追加してから登録してください」のようなメッセージを出して登録できないようにする。`order_items.product_id` が必須であり、商品が特定できないためである。

**数量／重量・仕入単価／仕入金額**

寸法と数量を入力した時点で重量を計算し、続けて仕入単価・仕入金額を自動計算する。計算ルールは basic-design.md「重量の計算」「最低保証重量」「明細金額」「定尺売りの単価」を参照。

事務ロールは価格マスタの一覧を参照できないため、明細の条件に該当する価格マスタの行だけをデータベースの関数（`security definer`）で取り出し、仕入単価の計算は `lib/pricing` で行う（table-design.md「価格マスタの権限と単価計算」を参照）。

- 重量の欄には合計重量（1 枚あたりの重量 × 数量）を表示する。ベタ丸・ドーナツは伝票に載る実重量、それ以外は単価の根拠にした重量（角重量。ササラは使用材重量）を表示する
- 仕入単価の欄には単位を添えて表示する（例: `202 /kg`、`1,216 /枚`）
- 仕入単価が別途見積もりになる行は「別途見積もり」と表示し、仕入金額は「—」とする。仕入単価は空欄のまま登録できる（後述「受注入力で扱わないもの」）

**摘要**

行末に、その明細だけに適用するフリーコメント（`order_items.field_note`）の入力欄を置く。中身がそのまま見える入力欄とし、開閉の操作は設けない（以前の「行末のチェックでコメントを開く」形は廃止）。

#### 加工の行（1 段）

区分で「9 加工」を選ぶか、材料の行で「+」を押すと加工の行（`order_item_processes`）になる。加工の行は 1 段で表示する。

| 欄の位置 | 内容 | 保存先 |
| --- | --- | --- |
| No | 「└」を表示し、直上の材料の行にぶら下がることを示す | |
| 切断方法／区分の位置 | 区分（9 加工） | |
| 種類〜材質の位置 | 加工方法（加工種別マスタの番号＋名称） | `process_type_id` |
| 品名の位置 | 加工内容（文字で入力。例: `1S / 12孔 38φ`） | `spec` |
| 数量の位置 | 加工数量 | `quantity` |
| 仕入単価の位置 | 単位（1 個 / 2 kg。初期値は 1 個）と加工の仕入単価（MVP では手入力） | `price_unit` / `unit_price` |
| 摘要の位置 | 摘要 | `remarks` |

入力順は「区分 → 加工方法 → 加工内容 → 数量 → 単位 → 仕入単価」で、仕入単価の後は次の行へ進む。

加工の仕入金額は単位によって求め方が変わる（円未満は切り上げ。basic-design.md「明細金額」を参照）。

| 単位 | 仕入金額 |
| --- | --- |
| 個 | 仕入単価 × 数量 |
| kg | 仕入単価 × 母材（直上の材料の行）の合計重量（母材の単価の根拠にした重量。角重量、ササラは使用材重量） |

- 数量・仕入単価・摘要は、材料の行と縦の位置を揃える
- 加工の行は直上の材料の行にぶら下がる（`order_item_id` は直上の材料の行）。そのため、材料の行より前（明細の先頭）には置けない
- 切断方法は表示しない（1 段に収めるため）。加工の行は材料の行にぶら下がるため、切断方法は母材のものとして扱う
- 加工の行は重量を持たない（材料の重量を二重に計上しないため）。kg 単位の加工は母材の重量を参照する
- 加工方法を入力した時点で、その加工に紐づく注意事項を補助エリアに追加で表示する

#### 合計

明細の下に、重量の合計・仕入金額の合計・単価未定の件数（別途見積もりで仕入単価が空欄の行数）を表示する。

仕入金額の合計には、材料の行に加えて加工の行の仕入金額も含める。重量の合計は材料の行の重量のみを合計する（加工の行は重量を持たないため）。

#### 仕入単価の表示と印刷

現場用伝票として印刷する際は仕入単価・仕入金額を表示しない。印刷時の表示切り替えで対応する。

### スプライス専用の受注

スプライスは通常の明細と混ざることがないため、明細の区分ではなく **受注単位** で切り替える。

ヘッダーの「スプライス」の番号の欄を 1 にすると、次のように画面が切り替わる（画面デザインの画像ではチェックボックスで表示しているが、テンキーで入力できるよう番号の欄とする）。

- ヘッダー 1 行目に「継手番号」（4〜6 文字。`orders.joint_no`）と「ショット」（0 無 / 1 有。`orders.splice_shot`）の欄を表示する
- 明細の上に「スプライス専用の受注」である旨の案内を表示する
- 明細はすべてスプライスになる（`special_product_type_id` はスプライス受注用の特殊製品種別）。品名の下段の区分名は「スプライス」と表示する
- 区分の欄は切断区分（1 寸法切 / 2 アイトレ）になり、`cutting_type` に保存する。アイトレは別途見積もりになる（`special_product_types.irregular_cut_quote_required`）
- ショットの有無は受注単位で持ち、全明細の仕入単価（ショット有無別の特殊製品単価）に使う

ショットが有のときは、補助エリアのスタンプに「ショット加工」を自動で追加し、「自動」の印を付けてチェック済み・変更不可で表示する。現場用伝票では目立つ位置に印字する。ショット加工のスタンプは `orders.splice_shot` から表示・印字するものとし、`order_stamps` には保存しない（ショットの有無と伝票の表示が食い違わないようにするため）。

### 補助エリア

横に 3 つの枠を並べる。

**注意事項**

得意先を選択した時点で、その得意先に紐づく注意事項を表示する。明細に加工方法を入力した時点で、その加工に紐づく注意事項を追加で表示する。得意先と加工の組み合わせに紐づく注意事項は、両方の条件が揃った時点で表示する。受注に関係のない注意事項は表示しない。

各注意事項には、どの条件で表示されたかの印（「得意先」「得意先 × ガス」「加工：キリ孔」など）を付ける。

**スタンプ**

登録済みの文言を一覧で表示し、チェックしたものが現場用伝票に印字される。得意先の指定スタンプ（`customer_stamps`）は、得意先を選択した時点で初期状態からチェックが入り、「客先指定」の印を付ける。

**フリーコメント**

受注全体に対するフリーコメント（`orders.field_note`）を入力する。明細ごとのコメントは各行の摘要に入力する。

### 受注入力で扱わないもの

次の項目は受注登録画面では入力しない。

| 項目 | 扱い |
| --- | --- |
| 梱包数（`order_items.package_count`） | 受注後のラベル発行メニューで入力する |
| 実重量（`order_items.actual_weight`） | 手入力が必要な行（アイトレなど）は、送り状発行の画面で必要な行だけ入力する。寸法切・ベタ丸・ドーナツのように寸法から求まるものは自動計算する |
| 別途見積もりの仕入単価 | 空欄のまま登録し、受注の修正（処理区分 1 変更）で後から入力する。受注一覧で「単価未定」（仕入単価が空欄の明細を含む受注）を絞り込めるようにする |
| 売上単価（`order_items.sales_unit_price`） | MVP の対象外。営業が決めるものであり、将来の営業システム連携（Phase2）で扱う。列は残すが MVP では使用しない |
| フリー区分（重量の手入力） | MVP では作らない。必要になれば区分に追加する |

### 入力時の挙動

| 操作 | システムの動作 |
| --- | --- |
| 処理区分で 1 変更・2 削除を選択 | 受注 No. の入力欄を有効にし、入力された受注を呼び出す |
| スプライスで 1 を入力 | 継手番号・ショットの欄を表示し、明細をスプライス専用に切り替える |
| ショットで 1 有を選択 | スタンプに「ショット加工」を自動で追加する（変更不可） |
| 得意先を選択 | 注意事項を表示、指定スタンプにチェック |
| 配達で 9 フリーを選択 | 文字を入力する欄を表示する |
| 切断方法で 9 定尺を選択 | 区分を 3 定尺に固定し、寸法欄を定尺サイズの入力に切り替える。製鋼法を「—」にする |
| 区分を選択 | 寸法の入力欄を区分に応じて切り替える。9 加工なら加工の行に切り替える |
| 種類を選択 | 材質・メーカーの選択肢を絞り込む。材質エキストラを適用しない種類なら製鋼法を「—」にする |
| 板厚を入力 | 取り扱いのない板厚なら行を強調表示してメッセージを出す |
| 縞板でメーカーまたは板厚を変更 | メーカーと板厚の組み合わせに単位質量が登録されているかを確認し、なければエラーを出す |
| 寸法・数量を入力 | 重量を計算し、仕入単価・仕入金額を自動入力する（別途見積もりなら「別途見積もり」と表示） |
| 加工方法を入力 | 該当する注意事項を表示 |
| 番号・寸法・数量の欄で「-」 | その行の摘要へ移動する |
| 登録 | 受注番号を採番し、現場用伝票を印刷 |
| 処理区分 2 削除で確定 | 受注を論理削除する。出荷実績がある受注はエラーを出して削除しない |

最低保証重量の判定（kg 単価か枚単価か）は入力者に選択させない。寸法と種類・材質から 1 枚あたりの重量を算出して自動判定する。

### 受注の削除

処理区分 2 削除は論理削除とする。受注の行は消さずに削除済みの印（`orders.deleted_at`）を付け、受注一覧・現場用伝票・送り状発行などの対象から外す。誤って削除した場合の確認や、過去の受注番号の追跡ができるようにするためである。

出荷実績がある受注は削除できない。処理区分 2 削除で呼び出した受注に出荷実績があれば、エラーを出して削除させない。DB 側でも同じ制限をかける（table-design.md `orders` の「論理削除」を参照）。

# 画面設計書

## 共通方針

### 対象環境

事務所の既存 PC で使用する。画面解像度は 1280 × 1024 を前提とし、モバイル・タブレット対応は行わない。ブラウザの UI 領域を除いた実質的な表示領域はおよそ 1280 × 900 として設計する。

利用者が限定され、使用する端末も固定されているため、レスポンシブ対応に工数を割かず、その解像度で最も使いやすい形に最適化する。

### レイアウトの考え方

現行の紙伝票の書式を画面上で再現し、伝票に直接打ち込む形式とする。

既存の業務フォーマットをそのままインターフェースとすることで、次の効果を狙う。

- 入力中に出力物の完成形が見えるため、印刷して初めて気づく誤りが減る
- 現場が受け取る伝票の見た目が変わらず、従来どおり扱える
- 印刷した伝票と画面を照合する作業が速い
- 新しい操作を覚える必要がなく、導入時の教育コストが低い

横スクロールは発生させない。伝票は横長だが、表示領域に収まるよう全体を縮尺調整する（CSS の `transform: scale()` などを用い、レイアウトを崩さずに収める）。縮小しすぎると入力しづらくなるため、実際の画面で確認しながら調整する。

## 受注登録画面

### 全体構成

画面を上下 2 つの領域に分ける。

```
┌─────────────────────────────────┐
│ 伝票エリア                        │
│  現行の紙伝票を再現したレイアウト     │
│  ヘッダー項目 + 明細行              │
│                                 │
├─────────────────────────────────┤
│ 補助エリア                        │
│  注意事項の表示                    │
│  スタンプ文言のチェック              │
│  フリーコメント入力                 │
└─────────────────────────────────┘
```

伝票が横長であるため縦方向に余白が生まれる。その領域を補助エリアとして使い、紙の伝票には存在しない入力項目を配置する。

表示領域に収まらない場合は、補助エリアのみをスクロールさせる。伝票エリアは常に表示されている状態を保ち、入力中に見失わないようにする。

### 伝票エリア

現行の紙伝票の書式をそのまま再現する。ヘッダーには得意先・客先担当・納入先・工事名・受注日・納期・仕入先を配置し、その下に明細行が並ぶ。

**明細の構造**

明細は材料の行と、それに紐づく加工の行で構成される。加工指示書では加工が重量ゼロの別行として印字されているため、画面上も同様に行として並べる。データ構造としては材料が親、加工が子となる。

**母材費の表示**

単価記入用の伝票と同じ位置に表示する。紙の伝票に単価の記入欄が存在するため、新たに配置場所を設ける必要がない。

現場用伝票として印刷する際は単価を表示しない。印刷時の表示切り替えで対応する。

### 補助エリア

**注意事項の表示**

得意先を選択した時点で、その得意先に紐づく注意事項を表示する。明細に加工種別を入力した時点で、その加工に紐づく注意事項を追加で表示する。

得意先と加工の組み合わせに紐づく注意事項は、両方の条件が揃った時点で表示する。受注に関係のない注意事項は表示しない。

**スタンプ文言のチェック**

登録済みの文言を一覧で表示し、チェックしたものが現場用伝票に印字される。得意先に紐づく文言は、得意先を選択した時点で初期状態からチェックが入る。

**フリーコメント入力**

受注全体に対するものと、明細ごとのものを入力できる。明細ごとのコメントは、該当する明細行から入力する形とする。

### 入力時の挙動

| 操作 | システムの動作 |
| --- | --- |
| 得意先を選択 | 注意事項を表示、既定のスタンプ文言にチェック |
| 商品・切断方法・寸法を入力 | 単位重量を算出し、重量区分を判定して母材単価を自動入力 |
| 加工種別を入力 | 該当する注意事項を表示 |
| 登録 | 受注番号を採番し、現場用伝票を印刷 |

重量区分（2kg 以下か否か）は入力者に選択させない。寸法と材質から単位重量を算出して自動判定する。

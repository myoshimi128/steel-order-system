# 画面設計書

## 共通方針

### 対象環境

事務所の既存 PC で使用する。画面解像度は 1280 × 1024 を前提とし、モバイル・タブレット対応は行わない。ブラウザの UI 領域を除いた実質的な表示領域はおよそ 1280 × 900 として設計する。事務所の PC は画面 1 枚で使う（注文書と入力画面を別々の画面に並べられない）。

利用者が限定され、使用する端末も固定されているため、レスポンシブ対応に工数を割かず、その解像度で最も使いやすい形に最適化する。

### レイアウトの考え方

画面の見た目は、受付〜受注登録の画面イメージ（docs/intake/screen-design.md の各画面）にそろえる。白・薄いグレーを基調にした白いカードを並べ、アクセントはネイビーとする（「共通レイアウト」の「色」）。

以前は現行の紙伝票の書式を画面上で再現し、伝票に直接打ち込む形式（材料の行を 2 段にした伝票の形）としていた。受付の機能を統合する際に、注文書を画面の左に表示しながら入力する形（受注登録の画面イメージ）に合わせ、明細は 1 件 1 行の表に改めた。現場に渡す現場用伝票の書式は、印刷の機能で従来どおりの形にする（入力画面の見た目とは切り離す）。

横スクロールは発生させない。1280px の画面で、注文書のパネルを開いたまま明細の表が収まるよう、列の幅を決める（「受注登録画面」の「明細の表」）。縮尺（`transform: scale()`）で縮めると入力欄や文字まで小さくなるため、縮尺ではなく列の幅で収める。

## 共通レイアウト

ログイン画面以外のすべての画面に、共通のヘッダーとサイドメニューを置く。受付〜受注登録の各画面（docs/intake/screen-design.md）も同じ枠を使う。

```
┌──────────────────────────────────────────────┐
│ [ロゴ] システム名  › パンくず           🔔 [営業所・部署 氏名] [ログアウト] │ ← ヘッダー（ネイビー）
├────────┬─────────────────────────────────────┤
│ サイド  │                                       │
│ メニュー │  各画面の中身                            │
│ （開閉） │                                       │
│        │                                       │
│ «閉じる │                                       │
└────────┴─────────────────────────────────────┘
```

**ヘッダー**

- ネイビーの帯に、ロゴ・システム名・パンくず・通知ベル・ユーザー（所属する営業所と部署、氏名。例:「本社シャーリング部 ○○」）・ログアウトを並べる
- 通知ベルには未読の件数を表示し、開くと未読の一覧を表示する。新着は右上にトースト（5 秒）で知らせる（docs/intake/screen-design.md「通知（画面側）」）

**サイドメニュー**

- メニューの階層は basic-design.md「画面構成」のとおり。ホームでは部署・営業所・共通のメニュー、部署の画面ではその部署の業務メニュー（件数のバッジつき）を表示する
- まだ作っていない画面のメニューは表示するが押せない（準備中）。件数のバッジは、対象のデータがまだない間は表示しない
- 開閉できる。閉じるとアイコンだけの幅（64px）になる
- 開閉の状態は cookie に保存する。localStorage はサーバーから読めず、画面を開いた瞬間にいったん開いた状態で描かれてちらつくため、サーバーが最初から正しい状態で描けるよう cookie にする
- 受注登録の画面は、初期状態で閉じる。注文書のパネルと明細の表に幅を使うためである

**色**

- 白・薄いグレーを基調とし、アクセントはネイビー（#1b365d）
- 赤（#c0392b）は、至急・要相談・重要・必須の印と、入力のエラーにだけ使う
- 初期値と違う値の強調（受注登録の明細の「初期値と違う値の強調」）には、赤と区別できるオレンジ系の色を使う
- アイコンはモノクロの線のアイコンとする
- 色は `globals.css` に名前を付けて定義し、画面ごとに色の値を直接書かない

**対象解像度との関係**

1280 × 1024 の画面で、ヘッダー（約 64px）とサイドメニュー（開いているとき約 240px、閉じているとき 64px）の分だけ中身の領域が狭くなる。受注登録の画面はサイドメニューを閉じた状態で、中身の幅 1216px（左右の余白 24px ずつを除いて 1168px）に収める。

- シャーリング部の部署ホーム（`/shearing`）は、本来の画面（docs/intake/screen-design.md「S-02」）ができるまで、受注登録・マスタ管理への入口だけを置いた仮のページとする

## 受注登録画面

画面イメージは、受付〜受注登録の設計の S-06c 受注情報・S-06d 注文内容（docs/intake/screen-design.md）に合わせる。ただし明細の表の列・番号の付け方・キー操作は本章のとおりとする（画面イメージの英字のコードは使わない）。

`docs/images/受注登録（通常）@1x.png`・`docs/images/受注登録（スプライス専用）@1x.png` は、伝票の形だった頃のデザインであり、項目と入力の考え方の参考として残す。

### 用語：仕入単価

この画面で自動計算する単価・金額は、すべて **仕入単価・仕入金額** である（価格マスタから求める自社の仕入値）。売上単価は営業が決めるものであり、MVP では扱わない。

仕入単価・仕入金額は、受注登録の画面には **表示しない**。自動計算と保存の仕組みは残し、単価の確認・入力・修正は後工程の「仕入入力」の画面で行う（basic-design.md「仕入入力」）。

### 画面の流れ

受注登録は 2 つの画面で入力する。1 つのページの中で ① → ② と進み、画面を移っても入力した内容は消えない。

```
受注登録待ち（S-06a）→ ① 受注情報 → ② 注文内容 → 登録して現場用伝票を印刷
```

| 画面 | 入力するもの |
| --- | --- |
| ① 受注情報 | 処理区分・受注No.・受付No.・部材区分（SPL のときは継手番号・ショット）・受注日・売り先・客先担当・入れ先・工事名・納期・配達・加工場所。受付No. は受付の機能ができるまで表示だけ。担当者は受付の機能と同じ PR で加える（後述「① 受注情報」） |
| ② 注文内容 | 明細（材料の行・加工の行）。得意先の注意事項を見ながら入力する。明細の表の下の帯でスタンプ・フリーコメントを入力し、② で登録する。明細ごとの摘要は使わない（伝えたいことはフリーコメントに書く） |

以前は ③ 伝票の指示（スタンプ・フリーコメント）を別の画面にしていたが、② にまとめた。画面を 1 つ減らして登録までの操作を短くするためである。

- 2 つの画面とも、上部に進み具合（① 受注情報 → ② 注文内容。受付の機能ができたら先頭に「受注登録待ち」）を表示する
- サイドメニューは閉じた状態で始める（「共通レイアウト」）
- 受付の機能ができるまでは、サイドメニューの「受注登録」から ① を直接開く。受付の機能ができたら、受注登録待ちの一覧（S-06a）から始める
- 処理区分 1 変更・2 削除は、① で受注No. を入力して呼び出す

### 全体構成

```
┌ 受注登録   ① 受注情報 ─ ② 注文内容 ───────────────────────────────┐
│ ┌ 注文書のパネル ─────┐┃┌ 画面ごとの中身（カード） ───────────────────┐ │
│ │ 注文書（PDF）         │┃│ ① 受注情報の入力欄                              │ │
│ │                      │┃│ ② 受注情報の要約・得意先の注意事項・明細の表・    │ │
│ │                      │┃│    スタンプとフリーコメントの帯                    │ │
│ │                      │┃│                                                │ │
│ └──────────────┘┃└────────────────────────────┘ │
│ （┃ はドラッグでパネルの幅を変えるつまみ）  キー操作の案内       [戻る] [次へ] │
└──────────────────────────────────────────────────────┘
```

**注文書のパネル**

2 つの画面の左に、注文書を表示するパネルを置く。事務所の PC は画面 1 枚のため、注文書を別のウィンドウに出すと入力画面と重なってしまう。画面の中で注文書を見ながら入力できるようにする。

- パネルの右端のつまみをドラッグして幅を変えられる。幅は cookie に保存し、次に開いたときも同じ幅にする（サイドメニューの開閉と同じ考え方。サーバーが最初から正しい幅で描けるようにする）
- 幅の範囲は 240px から「右の中身（明細の表など）が収まる幅」まで。1280px の画面では、明細の表が収まるよう最大 326px になる。広い画面では、より広く取れる。保存した幅が今の画面で広すぎる場合は、収まる幅に縮めて表示する
- 初期の幅は、右の中身が収まる範囲で最も広い幅とする
- **F2** キーでパネルを開閉する（どの欄にいても効く）。閉じると細い帯だけになり、右の中身が広がる。パネルの上の「閉じる」ボタンでも開閉できる。F2 は、テンキーの入力と重ならず、ブラウザの標準の操作（F1 ヘルプ・F5 再読み込み・F11 全画面・F12 開発ツール）とも重ならないため選んだ
- パネルの中で PDF を拡大・縮小・スクロール・ページ送りできる。ブラウザに入っている PDF の表示機能をパネルの中に埋め込んで使う（新しいライブラリは使わない）
- 受付の機能ができるまでは、注文書がシステムに入っていないため、パネルには「注文書はまだありません」とだけ表示する。受付の機能ができたら、受付に保存された注文書 PDF（タブ「注文書」）と図面データ（タブ「図面データ」）を表示する（docs/intake/screen-design.md「DocumentViewer」）

**画面の下部**

- キー操作の案内を常に表示する。よく使うキー（Enter・/・F3・F4・*・+）のうち今の画面で使えるものだけを並べ（① は Enter・/、② は 6 つすべて）、残りのキーは「キー操作の一覧」のボタンで開く一覧で見る（後述「キー操作」）。画面イメージ（S-06d）の案内の並べ方に合わせ、案内が長くなりすぎないようにするためである
- ボタン: ① は「クリア」「受注情報を確定して次へ」、② は「受注情報に戻る」「登録して現場用伝票を印刷」

### 入力方式

明細が多い受注でも手早く入力できるよう、**テンキーだけで入力を完結できるコード入力** とする。

- 選択する項目はすべて「番号の欄 ＋ 名称表示」とする。番号を打つと、右側に名称が表示される
- 初期値がある項目は Enter だけで次の項目へ進める
- 番号が分からないときは「/」（または End）で選択肢の一覧を開き、番号を打つか ↑↓ で選んで Enter で確定する
- 番号の欄は、上限の桁まで打つと Enter を押さなくても次の項目へ進む（後述「番号の桁数と自動で次へ」）
- ① を開いたときは、最初の項目（処理区分）にカーソルを置く。② に進んだときは明細の最初の行の「切断・区分」にカーソルを置く

**「0 はいつもの値（初期値）」**

番号で選ぶ項目では、最も多く使う値に番号 0 を割り当て、その項目の初期値にする。初期値の項目はいつもの値なら Enter だけで次へ進めるため、打つ数字を減らせる。

| 項目 | 番号 0（初期値） |
| --- | --- |
| 処理区分 | 0 新規 |
| 部材区分 | 0 無分類 |
| 入れ先 | 0 売り先と同じ（受付から入る場合は、受付の入れ先の 1 件目） |
| 種類 | 0 普通板 |
| 材質 | 0 SS400（材質を選ぶ種類のとき） |
| メーカー | 0 指定なし |

新しい選択肢をマスタに追加するときも、番号 0 は「いつもの値」のために取っておく。製鋼法は材質ごとに初期値が決まる（後述「種類・材質・製鋼法」）ため、この考え方の対象外とする。加工場所も、受付やログイン中のユーザーの営業所から必ず初期値が入るため、番号 0 は使わない。

受付から登録する受注では、受注情報の項目の初期値は受付の値になる（docs/intake/basic-design.md「受注情報」）。上の表の初期値は、受付に値がない場合のものである。

**検索付きの一覧（売り先・入れ先）**

売り先・入れ先は件数が多く番号を覚えていないことがあるため、「/」（または End）で開く一覧に検索の欄を付ける。受注情報の入れ先では、一覧の先頭に受付に登録した入れ先を「受付 1」「受付 2」…の印を付けて並べ、その下に納入先マスタの検索結果を出す（docs/intake/screen-design.md「受注情報の入力欄」）。選択肢の少ない欄（処理区分・納期種別・配達など）は、検索なしの一覧のままとする。

- 一覧を開くと検索の欄にフォーカスが移り、ふりがな・名前のどちらでも部分一致で検索できる
- 打つたびに候補が絞られる。↑↓ で選んで Enter で、番号と名称が入り次の項目へ進む
- Esc で一覧を閉じ、番号の欄に戻る
- ひらがな／カタカナ、全角／半角、英字の大文字／小文字の違いは区別しない。空白は無視する（「株式会社 サンプル」を「株式会社サンプル」でも探せる）
- 日本語入力の変換中の Enter・↑↓ は変換の操作として扱い、候補の選択には使わない
- ふりがなは得意先・納入先マスタの `name_kana` を使う。ふりがなが未登録の行も名前で検索できる

検索の正規化と絞り込みは `lib/code-input/search.ts`、一覧の表示は共通部品 `CodeList`（検索の有無を切り替えられる）に実装している。

**番号の桁数と自動で次へ**

番号の欄には上限の桁数を設け、上限の桁まで打つと Enter を押さなくても次の欄へ進む（現行のシステムと同じ）。マスタのコード・番号も同じ桁数に合わせ、マスタ管理の画面と DB の制約で制限する（table-design.md「制約」）。

| 画面 | 欄 | 上限 | マスタのコード・番号 |
| --- | --- | --- | --- |
| ① | 処理区分・納期種別・部材区分・ショット | 1 桁 | （定数） |
| ① | 売り先 | 4 桁 | 得意先コードは数字 4 桁（固定） |
| ① | 入れ先 | 4 桁 | 納入先コードは数字 4 桁（固定）。「0 売り先と同じ」だけは 1 桁 |
| ① | 配達 | 1 桁 | 配達方法の番号 0〜9 |
| ① | 加工場所 | 1 桁 | 営業所の番号 1〜9 |
| ① | 受注日・納期の日付 | 上限なし（Enter） | 4 桁（月日）と 8 桁（年月日）のどちらでも打てるため |
| ② | 切断・区分 | 2 桁 | （定数＋特殊製品種別の番号 0〜9）。「9 加工」は 1 桁で加工の行に切り替わる |
| ② | 種類 | 1 桁 | 種類の番号 0〜9 |
| ② | 材質 | 1 桁 | 材質の番号 0〜9。10 種類目が必要になったら 2 桁に広げる |
| ② | 製鋼法・定尺サイズ・曲げのヶ所・曲げ方 | 1 桁 | （定数） |
| ② | メーカー | 1 桁 | メーカーコードは数字 1 桁（固定。0 指定なし、1〜9 各メーカー） |
| ② | 板厚 | 数字 2 桁 | 商品の板厚は数字 2 桁まで（0.1〜9.9 と 1〜99 の整数） |
| ② | 縦・横・外径・内径・数量・孔数・穴径・曲げのヶ所数 | 上限なし（Enter） | — |
| ② | 加工方法 | 2 桁 | 加工種別の番号 10〜99（2 桁固定） |
| ② | スタンプの番号 | 2 桁 | スタンプの番号 1〜99。Enter で付け外しする欄のため、桁がそろっても自動では進まない |

- 上限の桁を超える数字は入らない
- 上限の桁まで打ったとき、存在する番号なら次の欄へ進む。存在しない番号なら進まず、その欄に「存在しない番号です」のエラーを出す
- 上限より短くても、存在する番号で、それより長い番号の先頭にもならないときは進む。切断・区分の「9」（9 で始まる 2 桁の番号はない）がこれに当たり、打った時点で加工の行に切り替わる
- 打って桁がそろったときだけ進む。消して短くしたときや、桁がそろった欄に戻ってきただけのときは進まない
- 板厚は小数点を数えず、数字の数で数える。16・40・1.6・4.5 は 2 桁なので自動で次へ進み、9 のような 1 桁は Enter で進む
- 桁数は `lib/code-lengths.ts`、自動で進むかの判定は `lib/code-input/auto-advance.ts` に置く

**キー操作**

| キー | 動作 |
| --- | --- |
| Enter | 次の項目へ進む（明細の行は、行の最後の欄の後で次の行へ進む） |
| Shift + Enter | 前の項目へ戻る |
| ↑ / ↓ | 前の項目 / 次の項目へ移る（すべての欄。下記の例外あり） |
| / または End | 選択肢の一覧を開く（一覧では番号か ↑↓ で選んで Enter、Esc で閉じる）。テンキーだけで操作できるよう「/」を基本とし、End でも開けるようにする |
| F2 | 注文書のパネルを開閉する |
| *（明細） | 直前の材料の行を加工の行ごと複写する（加工の行の上では何もしない） |
| - → 行番号 → Enter（明細） | 「切断・区分」の欄で「-」を押してから行番号を打ち Enter を押すと、その番号の材料の行を加工の行ごと複写する |
| +（明細） | 加工の行を追加する |
| F3 または Ctrl + Insert（明細） | 行を挿入する |
| F4 または Ctrl + Delete（明細） | 行を削除する（材料の行は加工の行ごと） |

文字を入れる欄（工事名・加工内容・曲げ方のフリー・フリーコメントなど）では、`/` `*` `+` `-` は普通の文字として入力する。

受付No.・受注No. の欄では、`-` をハイフンとして入力する（`26-1003-1`）。テンキーの `-` で打てるようにするためである。

明細の「-」は、以前は摘要へ移動するキーだったが、明細ごとの摘要を使わなくなって空いたため、行番号を指定した複写に使う。行番号を指定した複写は、以前は「行番号 → *」だったが、切断・区分が 2 桁で自動で次へ進むようになり、行番号と区別できなくなった（「12」と打つと 12 シャー型切りとして進む）ため、「-」で始める形に変えた。

画面下部の案内には、この表のうちよく使うキー（Enter・/・F3・F4・*・+）だけを出す。表の全部のキーは、案内の右の「キー操作の一覧」を押すと開く一覧で見られる（マウスで開閉する。Enter の順路には含めない）。キーの定義は `lib/order-entry/key-guide-items.ts`。

存在しない番号を入力した欄では、エラーを表示して次の項目へ進ませない。文字の欄では、日本語入力の変換を確定する Enter では次の項目へ進まない。

↑ ↓ による移動は、すべての欄で同じように動く（入力順は Enter と同じ）。← → は今までどおり欄の中の文字の移動に使う。次の場合は ↑ ↓ で欄を移動しない。

- 「/」で一覧を開いているとき（↑ ↓ は候補の選択に使う）
- 日本語入力の変換中（↑ ↓ は変換候補の選択に使う）
- 入力順に含まれない欄（一覧の検索の欄）

実装は `lib/hooks/use-field-navigation.ts` の `handleArrowKeys` を画面全体の外枠で受け取り、欄ごとには処理を書かない。

**日付の入力**

日付の欄（受注日・納期）も数字だけで入力する。

| 入力 | 解釈 |
| --- | --- |
| 4 桁（例: `1005`） | 今年の 10 月 5 日 |
| 8 桁（例: `20261005`） | 2026 年 10 月 5 日 |

入力した日付は `2026/10/05` の形で表示し直す。存在しない日付（2 月 30 日など）はエラーにして次の項目へ進ませない。「今年」は日本時間の今日の年とする。

キー割り当ては現行システムに合わせず、ブラウザの標準操作と衝突しないよう独自に設計した。行の挿入・削除の F3・F4 は、受付〜受注登録の画面イメージに合わせて追加した（以前の Ctrl + Insert・Ctrl + Delete も使える）。

### ① 受注情報

受注のヘッダーに当たる項目を入力する。受付登録の画面と同じ入力欄のコンポーネントを使い回し、受付で入れた値を初期値として表示する（受付から入った値は薄い青で表示する。受付の機能ができてから）。左には注文書のパネルを置く。

画面イメージ S-06c に合わせ、上部の帯に受付No. と受注No. を大きく出し、その下に項目名を欄の上に置いた入力欄を 2 列で並べる。加工場所と部材区分は、選択肢を「[番号] 名前」のボタン状に並べ、選ばれているものをネイビーの枠で示す（番号の欄にテンキーで番号を打って選ぶ。ボタンをマウスで押しても選べる）。

```
┌ 受付No.（受付と連携後に表示）         │ 受注No.（登録時に採番）              ┐ ← 帯（表示のみ）
├──────────────────────────────────────────────┤
│ 処理区分                             │ 受注日                           │
│ 売り先 *                             │ 納期（種別＋日付）                 │
│ 客先担当                             │ 配達（フリーのときは文字の欄）       │
│ 工事名                                                                  │
```

Enter で左上から右下へ順に進む（処理区分 → 受注日 → 売り先 → 納期 → 客先担当 → 配達 → 工事名 → 入れ先 → 加工場所 → 部材区分 → 継手番号・ショット）。最後の欄で Enter を押すと「受注情報を確定して次へ」へ移り、② に進む。担当者は受付の機能と同じ PR で加える。

- 受付No.: 受付のテーブルができるまでは表示だけの欄にし、「受付と連携後に表示」と添える。受付の機能ができたら、受注登録待ちの一覧で選んだ受付の番号を出す
- 受注No.: 「登録時に採番」と表示する。今の番号の形（年 2 桁＋連番）のまま採番し、受付の機能ができたら受付No.＋枝番に変える
- 部材区分の選択肢は、画面イメージに合わせて 1 DF / 2 GPL / 3 BH / 4 SPL / 0 無分類 の順に並べる（初期値は 0 無分類）

| 項目 | 保存先 | 必須 | 補足 |
| --- | --- | --- | --- |
| 処理区分 | —（画面の動作を切り替える） | | 0 新規なら受注 No. は登録時に採番。1 変更・2 削除なら受注 No. を入力して既存の受注を呼び出す。削除は論理削除（後述） |
| 受注 No. | `orders.order_no` | | 新規では「（登録時に採番）」と表示し入力不可。受付の機能ができたら「26-1003-2（登録時に採番）」のように次の枝番を表示し、この受付の登録済みの受注も並べて表示する |
| 部材区分 | `orders.member_class` | | 番号の欄。0 無分類（初期値）/ 1 DF / 2 GPL / 3 BH / 4 SPL。4 SPL にするとスプライス専用の受注になる（後述） |
| 継手番号・ショット | `orders.joint_no` / `orders.splice_shot` | | 部材区分が SPL のときだけ表示する（後述「スプライス専用の受注」） |
| 受注日 | `orders.order_date` | ○ | 今日を初期値として自動で入れ、必要な場合のみ変更する |

| 売り先（得意先） | `orders.customer_id` | **○** | 得意先コード（数字のみ）で入力する。選択すると注意事項の表示・指定スタンプのチェックが行われる |
| 客先担当 | `orders.customer_contact` | | 得意先側の窓口担当者。受注ごとに異なるため自由入力 |
| 入れ先（納入先） | `orders.delivery_destination_id` | | 番号の欄。初期値は受付の入れ先の 1 件目（受付になければ「0 売り先と同じ」）。別の納入先に届ける場合は納入先コード（数字のみ）を入力する（後述「入れ先が売り先と同じ場合」） |

受注番号は登録時に自動で採番する。登録の操作をした人（`orders.created_by`）も自動で記録する。仕入先は受注情報に置かない。

**納期の初期値**

受付の納期から次のように決める（docs/intake/basic-design.md「納期の決まり」）。受注で納期を変えても、受付の納期は書き換えない。

| 受付の納期 | 受注の納期の初期値 |
| --- | --- |
| 日付あり（確定） | 1 確定＋その日付 |
| 日付あり（仮納期） | 2 仮納期＋その日付 |
| 3 後報（未定） | 3 後報 |
| 4 最短出荷 | 4 最短出荷 |

売り先・入れ先のコードはテンキーで入力できるよう数字のみとする。

**入れ先が売り先と同じ場合**

入れ先の番号の欄は、受付に入れ先がなければ「0 売り先と同じ」を初期値とする（受付で「0 売り先と同じ」を登録した場合も同じ）。0 は納入先マスタの行ではなく、入れ先が売り先と同じであることを表し、保存時は `orders.delivery_destination_id` を NULL にする（メーカーの「0 指定なし」と同じ考え方）。区別できるよう、納入先マスタのコードに 0 は使えない。

受注の表示（一覧・詳細）や印刷（現場用伝票・送り状など）で `delivery_destination_id` が NULL のときは、売り先の名前を入れ先として出す。入れ先を空欄で表示することはしない。

### 明細

明細は材料の行と、それに紐づく加工の行で構成される。加工指示書では加工が重量ゼロの別行として印字されているため、画面上も同様に行として並べる。データ構造としては材料が親（`order_items`）、加工が子（`order_item_processes`）となる。

#### 明細の表（1 件 1 行）

材料の行は 1 件を 1 行に並べる。種類・製鋼法・メーカーも常に列として見せる。製鋼法やメーカーの指定は見落としやすく、隠すと誤りに気づきにくいためである。

| 列 | 幅 | 材料の行 | 加工の行 |
| --- | --- | --- | --- |
| No | 28px | 行番号（材料の行だけに 1 から振る） | 「└」（直上の材料の行にぶら下がる） |
| 切断・区分 | 128px | 切断・区分の番号＋短い名称（例: `42 レーザーアイトレ`） | 「9 加工」と加工方法の番号＋名称（切断・区分〜製鋼法の 4 列を使う） |
| 種類 | 72px | 番号＋名称 | （加工方法） |
| 材質 | 88px | 番号＋名称 | （加工方法） |
| 製鋼法 | 64px | 番号＋名称（入力しない行は「—」） | （加工方法） |
| メーカー | 72px | コード＋名称（長い名前は省略し、マウスを乗せると全体を表示） | 加工の項目（メーカー〜品名・寸法の 2 列を使う） |
| 品名・寸法 | 196px | 板厚 × 寸法（区分による。後述） | （加工の項目） |
| 数量 | 48px | 数量 | 加工数量（穴・曲げは自動計算） |
| 重量 | 64px | 重量（自動） | なし |

列の間隔は 4px で、表の幅は 792px になる。1280px の画面では、中身の幅 1168px から、表の左右の余白（12px ずつ）・スクロールバー（8px）・カードの枠（1px ずつ）・パネルとの間隔（16px）を除いて、注文書のパネルに最大 326px を取れる。列の幅は `components/order-entry/items/item-grid.ts` にまとめる。

- 寸法の入力欄は固定の幅とし、広い画面でも引き伸ばさない（板厚 44px、縦・横・直径・外径・内径 60px）
- 注文書のパネルを狭くしたり閉じたりして右の中身が広くなっても、列の幅は変えない（入力欄を間延びさせないため）
- 区分の名前は短い名前にする（例: 「レーザーアイトレ」「シャー型切り」）。表の中と一覧（「/」）で同じ名前を使う。列に収まらない名前は省略し、マウスを乗せると全体を表示する

**初期値と違う値の強調**

種類・材質・製鋼法・メーカーで、初期値と違う値の欄は、太字にして色（オレンジ系。`attention`）で強調する。高炉の指定やメーカー指定などの見落としを防ぐためである。

| 欄 | 強調する条件 |
| --- | --- |
| 種類 | 0 普通板以外（縞板・ボンデ・ミガキ） |
| 材質 | 0 SS400 以外 |
| 製鋼法 | その材質の初期値（`materials.default_steel_making`）と違う（例: SN490C を電炉にしたとき。SN490C を高炉のままにしたときは強調しない） |
| メーカー | 0 指定なし以外 |

**切断・区分の番号**

切断方法と区分を 1 つの番号の欄にまとめる。十の位が切断方法、一の位が区分である。テンキーで打てるよう英字は使わない。

| 十の位（切断方法） | 1 シャーリング / 2 ガス / 3 プラズマ / 4 レーザー / 7 定尺 |
| --- | --- |
| 一の位（区分） | 1 寸法切 / 2 アイトレ（シャーリングでは「型切り」と表示）/ 5 ササラ / 7 ベタ丸 / 8 ドーナツ（特殊製品は特殊製品種別マスタの番号） |

| 番号 | 名称（表の中） | `cutting_method` | `cutting_type` | `special_product_type_id` | 寸法の入力欄（板厚の後） |
| --- | --- | --- | --- | --- | --- |
| 11 | シャー寸法切 | シャーリング | 寸法切 | NULL | 縦 × 横 |
| 12 | シャー型切り | シャーリング | アイトレ | NULL | 縦 × 横 |
| 21 / 31 / 41 | ガス・プラズマ・レーザー寸法切 | ガス / プラズマ / レーザー | 寸法切 | NULL | 縦 × 横 |
| 22 / 32 / 42 | ガス・プラズマ・レーザーアイトレ | ガス / プラズマ / レーザー | アイトレ | NULL | 縦 × 横 |
| 25 / 35 / 45 | ガス・プラズマ・レーザーササラ | ガス / プラズマ / レーザー | NULL | ササラ | 使用材の寸法（縦 × 横） |
| 27 / 37 / 47 | ガス・プラズマ・レーザーベタ丸 | ガス / プラズマ / レーザー | NULL | ベタ丸 | 直径 |
| 28 / 38 / 48 | ガス・プラズマ・レーザードーナツ | ガス / プラズマ / レーザー | NULL | ドーナツ | 外径 × 内径 |
| 71 | 定尺 | NULL | NULL | NULL | 定尺サイズ（1 3x6 / 2 4x8 / 3 5x10）。保存先は `plate_size` |
| 9 | 加工 | — | — | — | 加工の行に切り替わる（後述「加工の行」） |

- シャーリングの型切りは、アイトレと同じ扱いとする（新しい切断区分は作らない）。保存する値は `アイトレ` で、重量・単価の計算もアイトレと同じ（切断単価もアイトレの行を使う）。表示だけを「型切り」にする
- 特殊製品はシャーリングでは作らないため、シャーリングと特殊製品の組み合わせ（15・17・18）はない
- 特殊製品の組み合わせの番号は、特殊製品種別マスタの番号から組み立てる（種別を追加すると、ガス・プラズマ・レーザーとの組み合わせの番号が増える）。特殊製品種別の番号は、区分の 1・2 と重ならない値にする
- ガス・プラズマで切ったベタ丸・ドーナツは別途見積もりになる。種別の名前で分岐せず、特殊製品単価に切断方法の条件を持たせて決める（basic-design.md「特殊製品の単価」）
- スプライスは通常の受注の一覧に出さない。スプライスはスプライス専用の受注で扱う（後述）
- 定尺（71）は切断を伴わないため、保存時は `cutting_method` を NULL にし、製鋼法を「—」にする
- 以前は切断方法（1 シャーリング / 2 ガス / 3 レーザー / 4 プラズマ / 9 定尺）と区分（1 寸法切 / 2 アイトレ / 3 定尺 / 9 加工 / 特殊製品の番号）を別々の欄で入力していた。DB には番号ではなく値を保存しているため、番号の付け方を変えてもデータには影響しない

特殊製品（ササラ・ベタ丸・ドーナツ）の寸法の入力欄は、種別名ではなく特殊製品種別マスタの「寸法の形」（`special_product_types.dimension_shape`：角 / 円 / ドーナツ）で切り替える。ドーナツの外径・内径は、欄の見出しを付けず、空欄の中の薄い文字（「外径」「内径」）で示す（列の幅に収めるため）。

板厚は `products` から特定する商品に含まれるため、明細には直接保存しない。商品の形状（定尺 / 大板）は寸法から判定する（basic-design.md「定尺と大板の判定」）。

#### 材料の行

入力順は「切断・区分 → 種類 → 材質 → 製鋼法 → メーカー → 板厚 → 寸法 → 数量」で、数量の後は次の行へ進む。最後の行で数量の後に Enter を押すと、新しい行を追加してその行へ進む。

入力しない欄（材質のない種類の材質、「—」の製鋼法）は入力順に含めない。何も入力していない最後の行の「切断・区分」で Enter を押すと、明細の入力を終えたとして、下の帯のスタンプの番号の欄へ移る（何も入力していない行は保存しない）。

**行の操作**

| キー（明細の番号・寸法・数量の欄） | 動作 |
| --- | --- |
| * | 直前の材料の行の内容（数量も含む）を、ぶら下がる加工の行ごと今の行に写す。写した加工の行は、写した材料の行のすぐ下に入る。新しい空の行で使う想定。写せる材料の行がなければ案内を表示する |
| - → 行番号 → Enter | 「切断・区分」の欄で「-」を押すと、欄が「-」だけになる。続けて行番号（No 欄の番号）を打って Enter を押すと、その番号の材料の行を加工の行ごと今の行に写す。存在しない番号なら案内を表示し、欄を空に戻す。「-」を打ちかけたまま欄を離れると、欄を空に戻す |
| F4 / Ctrl + Delete | 今の行を削除し、次の行（なければ前の行）へ移る。材料の行を削除すると、ぶら下がる加工の行も一緒に削除する。最後の 1 行を削除した場合は空の行に置き換える |
| F3 / Ctrl + Insert | 今の行の前に空の行を挿入し、その行へ移る |
| + | 今の材料の行（加工の行の上で押した場合は母材）の加工の行の最後に、加工の行を追加してその行の加工方法へ移る |

加工も同じことが多いため、材料の行の複写は加工の行ごと行う。加工の行の上で「*」を押しても何もしない（同じ材料に同じ加工を 2 行入れることはなく、例えば 18φ の孔は「18φ 4つ」のように 1 行にまとめて入力するため、加工の行だけを写す操作は設けない）。

**品名・寸法の欄**

板厚に続けて、区分に応じた寸法を入力する（例: `40 × 660 × 660`、`9 × 300`（ベタ丸の直径）、`4.5 × 2 4x8`（定尺））。区分の名前は「切断・区分」の欄に出ているため、この欄には出さない。種類・材質・製鋼法・メーカーもそれぞれの列に出ているため、以前の「品名」（例: `SN490C 電炉`）の表示はなくした。現場用伝票の品名は、印刷のときに組み立てる。

**種類・材質・製鋼法**

種類の初期値は 0 普通板とする。材質の選択肢は、選んだ種類について商品マスタ（`products`）に登録されている組み合わせから絞り込む。現在の登録内容では次のようになる。

| 種類 | 材質の選択肢 |
| --- | --- |
| 普通板 | SS400、SM490A、SN400B など普通板として登録されている材質 |
| 縞板 | SS400 のみ |
| ボンデ・ミガキ | 材質なし（無規格） |

材質の初期値は 0 SS400 とし、材質を選ぶ種類（普通板・縞板）では最初から「0 SS400」が入った状態にする（Enter だけで次へ進める）。種類を変えて、今の材質が新しい種類で選べなくなった場合は、新しい種類に 0 の材質があればそれを、なければ空にする。

製鋼法の初期値は材質ごとに決まる（材質マスタの `default_steel_making`）。材質を入力・変更すると、製鋼法をその材質の初期値にする。そのあと手で変更できる（材質を変えない限り、手で変えた製鋼法はそのまま）。

| 材質 | 製鋼法の初期値 |
| --- | --- |
| SS400 | 1 電炉 |
| SN400B・SM490A・SN490B・SN490C・SN400C・SM400A・TMCP325C・TMCP385C | 2 高炉 |

ただし次の場合は製鋼法を「—」表示にして入力させず、`steel_making` を NULL で保存する。

- 区分が定尺のとき（定尺単価には高炉材加算がなく、製鋼法を使わないため）
- 種類が材質エキストラを適用しない種類のとき（`plate_types.applies_material_extra` が false。縞板・ボンデ・ミガキ）

**メーカー**

初期値は「0 指定なし」とし、客先から指定があった場合のみメーカーコードを入力する。

縞板のときは必須とし、選択肢は単位質量（`unit_weights`）が登録されているメーカーだけに絞る。縞板は単位質量がメーカーによって異なり、重量計算に必要なためである。

メーカーの選択時点では板厚が決まっていない（板厚は後の寸法欄で入力する）ため、メーカーの絞り込みは板厚を問わず「単位質量が 1 件でも登録されているメーカー」とする。メーカーと板厚のどちらかが変更されたら、その組み合わせに単位質量が登録されているかを確認し、なければエラーを出す（重量が計算できないため登録できない）。板厚を先に入力してから後でメーカーを変更した場合も、同じ確認を行う。

**取り扱いのない板厚**

種類・材質・形状（定尺 / 大板）と合わせて商品マスタに該当がない板厚の場合は、その行を強調表示し、行の下に「14mm は取り扱いがありません。商品マスタに追加してから登録してください」のようなメッセージを出して登録できないようにする。`order_items.product_id` が必須であり、商品が特定できないためである。板厚を入力した時点で、その種類・材質の商品が 1 つもなければ警告する。寸法を入れた後、定尺を超える部品なのに大板の商品がない場合も警告する。

**エラー・警告の表示**

明細の欄は狭いため、エラーのある欄は枠の色で示し、文章は行の下にまとめて表示する。エラーのある行は背景色を変える。

- 入力中から出すもの: 存在しない番号、取り扱いのない板厚、単位質量のないメーカー、数値として正しくない寸法・数量、材料の行より前に置いた加工の行、受注の種類（通常 / スプライス専用）で使えない区分
- 登録を押したときに出すもの: 上記に加えて、未入力の必須項目、単価を決められない行（後述）

**数量・重量**

寸法と数量を入力した時点で重量を計算する。計算ルールは basic-design.md「重量の計算」「最低保証重量」を参照。重量の欄には合計重量（1 枚あたりの重量 × 数量）を表示する。ベタ丸・ドーナツは伝票に載る実重量、それ以外は単価の根拠にした重量（角重量。ササラは使用材重量）を表示する。重量は単価の計算から切り離して求める。

**仕入単価（画面には出さない）**

仕入単価・仕入金額は画面に出さないが、入力に合わせて自動計算し、登録時に保存する（`order_items.cutting_unit_price` など）。計算ルールは basic-design.md「最低保証重量」「明細金額」「定尺売りの単価」「切断単価の自動計算」を参照。

事務ロールは価格マスタの一覧を参照できないため、明細の条件に該当する価格マスタの行だけをデータベースの関数（`security definer`）で取り出し、仕入単価の計算は `lib/pricing` で行う（table-design.md「価格マスタの権限と単価計算」を参照）。価格マスタの行を取得するタイミングは次のとおり。

- 行の入力から取得の条件（種類・材質・板厚・切断方法・区分・定尺サイズ・受注日）が決まったら、入力が落ち着くのを少し待ってから（0.3 秒）取得する
- 取得結果は条件ごとに画面に保存し、同じ条件の行では取得し直さない（同じ材質・板厚の行が続いても取得は 1 回）
- 寸法・数量は取得の条件に含めない。寸法や数量を変えただけなら、取得済みの行を使って画面側で計算し直す

- 別途見積もりになる行は、仕入単価を空欄のまま登録する。単価は後で仕入入力の画面で入力する（受注登録の画面では知らせない）
- 単価を決められない行（ショット・受注日・切断方法が未入力、取り扱いのない板厚、価格マスタの行の取得に失敗）は、登録を押したときに行の下にエラーを出して登録しない。入力を直すと単価が決まる

#### 加工の行

「切断・区分」で「9」を打つか、材料の行で「+」を押すと加工の行（`order_item_processes`）になる。「9」を打った場合は、同じ欄が加工方法の番号の欄に変わり、続けて加工方法の番号を打つ。加工方法の番号（例: 11 レーザー・プラズマ孔）は切断・区分の番号（例: 11 シャー寸法切）と重なるため、先に「9」で加工の行に切り替えてから打つ。

| 欄の位置 | 内容 | 保存先 |
| --- | --- | --- |
| No | 「└」を表示し、直上の材料の行にぶら下がることを示す | |
| 切断・区分〜製鋼法 | 「加工」の印と加工方法（加工種別マスタの番号＋名称） | `process_type_id` |
| メーカー〜品名・寸法 | 加工の項目（加工方法の「入力の形」で切り替える。後述） | `spec_fields`（自由入力は `spec`） |
| 数量 | 加工数量（穴・曲げは自動計算。自由入力は手入力） | `quantity` |

加工の単位（`price_unit`）と加工の仕入単価（`unit_price`）は受注登録では入力しない。単位は初期値の「個」、仕入単価は空欄で保存し、仕入入力の画面で入力する。摘要（`remarks`）は使わない（「スタンプ・フリーコメントの帯」）。

**加工の項目（入力の形）**

加工の項目の入力欄は、加工方法に選んだ加工種別の「入力の形」（`process_types.input_shape`）で切り替える。加工種別の名前では分岐しない。考え方は basic-design.md「加工の入力項目」を参照。

| 入力の形 | 加工の項目の入力欄 | 数量 | 伝票に載せる文（加工内容）の例 |
| --- | --- | --- | --- |
| 自由入力 | 加工内容（文字） | 手入力 | 入力した文のまま |
| 穴 | `1S/` 孔数 `孔` 穴径 `φ` | 1 枚あたりの孔数 × 母材の枚数（自動） | `1S/ 12孔 38φ` |
| 曲げ | ヶ所（番号）・曲げ方（番号）`曲げ`。それぞれ 9 フリーのときだけ、右に入力欄が現れる | 母材の枚数（自動） | `2ヶ所 二方曲げ`、`1ヶ所 90°曲げ`、`1ヶ所 R曲げ` |

- 穴: 孔数は 1 枚あたりの数（1 以上の整数）、穴径は mm（0 より大きい数。小数可）。どちらも必須
- 曲げ: ヶ所の初期値は「0 1ヶ所」、曲げ方の初期値は「0 90°」で、いつもの曲げなら Enter だけで進める。9 フリーのヶ所数は 1 以上の整数、曲げ方の文字は必須
- 曲げの文は「〇ヶ所 〇曲げ」に統一し、曲げ方の後ろには常に「曲げ」を付ける（`1ヶ所 90°曲げ`、`2ヶ所 二方曲げ`）。フリーの曲げ方は「曲げ」を除いた部分だけを入力する（`R` → `1ヶ所 R曲げ`、`85°` → `1ヶ所 85°曲げ`）。入力する部分が分かるよう、曲げ方の欄（フリーのときは文字の欄）の右に「曲げ」と表示する
- 自動計算の数量はグレーの表示にして入力させない（入力順にも含めない）。母材の枚数がまだ入力されていなければ「—」と表示する
- 母材の枚数を変えると、ぶら下がる穴・曲げの行の数量も追随する。行の挿入・削除で母材が変わった場合も、新しい母材の枚数で計算し直す
- 加工方法を別の入力の形の加工種別に変えても、それまでの項目の入力は消さない。保存するのは、今の入力の形で表示している項目だけとする（見えない項目は保存しない）。加工方法の番号を打ち直す途中（例: 20 キリ孔 → 2 → 21 タップ孔）で、いったん存在しない番号（自由入力の扱い）を経由しても、入力した項目が消えないようにするため
- 材料の行を「*」で複写したときは、加工の行の項目もそのまま写す（数量は写した先の母材の枚数で計算される）

入力順は入力の形によって変わる。最後の欄の後は次の行へ進む。

| 入力の形 | 入力順 |
| --- | --- |
| 自由入力 | 加工方法 → 加工内容 → 数量 |
| 穴 | 加工方法 → 孔数 → 穴径 |
| 曲げ | 加工方法 → ヶ所（→ ヶ所数）→ 曲げ方（→ 曲げ方の文字） |

加工方法がまだ決まっていない（または存在しない番号の）間は、自由入力の形として扱う。加工方法の欄を空にして Shift + Enter で戻ると、材料の行の「切断・区分」に戻せる（加工の行をやめる場合は F4 で行を削除する）。

- 加工の行は直上の材料の行にぶら下がる（`order_item_id` は直上の材料の行）。そのため、材料の行より前（明細の先頭）には置けない。何も入力していない材料の行は飛ばして、その上の材料の行を母材とする
- 加工方法と数量は必須（穴・曲げの数量は自動計算のため、代わりに入力の形ごとの項目が必須）
- 加工の行は重量を持たない（材料の重量を二重に計上しないため）
- 加工の注意事項（`process_notices`）に当てはまる行は、その行のすぐ下に注意を小さく表示する（エラーと区別するため色を変える）。加工種別と、母材の板厚・この行の穴径（入力の形が「穴」のとき）で判定する。表示のみで、登録は止めない
- 加工方法を入力すると、その加工種別を条件にした得意先の注意事項も表示される（後述「得意先の注意事項」）

#### 合計

明細の表の下に、数量の合計と重量の合計を表示する。どちらも材料の行だけを合計する（加工の行の数量は孔数などで単位が違い、重量は持たないため）。仕入金額の合計と単価未定の件数は表示しない（仕入入力で扱う）。

### スプライス専用の受注

スプライスは通常の明細と混ざることがないため、明細の区分ではなく **受注単位** で切り替える。

① の「部材区分」を 4 SPL にすると、スプライス専用の受注になり、次のように画面が切り替わる。

- ① の 1 行目に「継手番号」（任意。10 文字以内。`orders.joint_no`）と「ショット」（0 無 / 1 有。`orders.splice_shot`）の欄を表示する。ショットは部材区分を 4 SPL にした時点で初期値の「1 有」が入る（スプライスはショット有が多いため。無の場合は 0 に打ち直す）
- ② の明細の上に「スプライス専用の受注」である旨の案内を表示する
- 明細はすべてスプライスになる（`special_product_type_id` はスプライス受注用の特殊製品種別）
- 「切断・区分」で使える番号は、寸法切（11・21・31・41）、アイトレ（12・22・32・42。アイトレは別途見積もり）、9 加工だけになる。定尺・ササラ・ベタ丸・ドーナツは使えない。表の中の名称は通常の受注と同じ（例: `41 レーザー寸法切`）で、スプライス専用の受注であることは明細の上の案内で示す
- アイトレが別途見積もりになるのは、特殊製品種別のフラグ（`special_product_types.irregular_cut_quote_required`）で決める
- ショットの有無は受注単位で持ち、全明細の仕入単価（ショット有無別の特殊製品単価）に使う

明細を入力した後に ① に戻って部材区分を SPL とそれ以外の間で切り替えても、明細は消さずに残す。切り替え後の受注で使えない番号の行（例: スプライス専用の受注に切り替えたときの 71 定尺・ササラ・ベタ丸など）にはエラーを表示し、直すまで登録できない。

ショットが有のときは、② の下の帯のスタンプに「ショット加工」を自動で追加し、「自動」の印を付けてチェック済み・変更不可で表示する。現場用伝票では目立つ位置に印字する。ショット加工のスタンプは `orders.splice_shot` から表示・印字するものとし、`order_stamps` には保存しない（ショットの有無と伝票の表示が食い違わないようにするため）。

### 得意先の注意事項

得意先・切断方法・加工種別のうち、注意事項に指定した条件がすべて受注に当てはまったものだけを表示する（basic-design.md「注意事項の表示」）。切断方法と加工種別は、受注のどこかの行にあれば当てはまるとする。得意先を選んだとき、明細の切断・区分・加工方法を入力したときに、その場で表示を更新する。受注に関係のない注意事項は表示しない。

- ② の受注情報の要約の下に固定表示する（明細を打ちながら見えるように）。件数が多いときは 2 行まで表示し、残りは「ほか○件」として開けるようにする
- 当てはまる注意事項がなければ、帯ごと表示しない
- 各注意事項には、指定した条件を並べた印（「得意先」「得意先 × レーザー」「得意先 × キリ孔」など）を付ける
- 並び順は表示順（`priority`）の小さい順。同じなら条件の少ない順
- 加工の行ごとの注意（板厚・穴径による注意）は、ここではなく加工の行のすぐ下に表示する

### スタンプ・フリーコメントの帯

現場用伝票に載せる指示（スタンプ・フリーコメント）を、② の明細の表の下の帯で入力する（以前は ③ 伝票の指示として別の画面にしていた）。

- 帯の高さは固定（144px）にして低めにし、明細の行数を確保する。中身が収まらないときは枠の中でスクロールする
- 左にスタンプ、右にフリーコメントを並べる（幅は 3 : 2）
- 入力順は「明細 →（最後の空の行で Enter）→ スタンプの番号 → フリーコメント → 登録ボタン」とする。スタンプの番号の欄で Shift + Enter を押すと、明細の最後の行へ戻る

**明細ごとの摘要は使わない**

明細の行ごとの摘要（材料の行は `order_items.field_note`、加工の行は `order_item_processes.remarks`）は入力しない。特定の行について伝えたいこと（「3 行目は端材を返却」など）も、受注全体のフリーコメントに書く運用とする。行ごとの欄を 1 つずつ Enter で進む手間がかかり、ほとんどの行が空欄になるためである。DB の列は残し、登録時は NULL を入れる（table-design.md）。

**スタンプ**

登録済みの文言を番号順に一覧で表示し、チェックしたものが現場用伝票に印字される（`order_stamps` に保存）。テンキーだけで操作できるよう、枠の見出しの行に番号の欄を 1 つ置く。帯の高さに多く収まるよう、スタンプは 3 列に並べ、列に収まらない文言は省略する（マウスを乗せると全体を出す）。

| 操作 | 動作 |
| --- | --- |
| 番号を打って Enter | その番号のスタンプのチェックを付け外しする。欄は空に戻り、カーソルはそのまま（続けて別の番号を打てる） |
| 空のまま Enter | フリーコメントへ進む |
| 存在しない番号で Enter | エラーを表示して、欄に留まる |
| クリック | チェックを付け外しする（マウスでも操作できる） |

- スタンプの数は 10 件前後の見込みで、番号と文言が 3 列で枠に収まるため、「/」の一覧は設けない
- 番号は 2 桁まで（1〜99）。Enter で付け外しする欄のため、桁がそろっても自動では進まない
- 得意先の指定スタンプ（`customer_stamps`）は、得意先を選択した時点で初期状態からチェックが入り、「客先指定」の印を付ける。その受注だけ外すこともできる
- 手で付け外ししたスタンプは、あとから得意先を変えてもそのまま残す（入力者が意図して選んだものを消さないため）
- スプライス専用の受注でショットが有のときは、先頭に「ショット加工」を「自動」の印付き・チェック済み・変更不可で表示する。番号は持たず、保存もしない（「スプライス専用の受注」を参照）

**フリーコメント**

受注全体に対するフリーコメント（`orders.field_note`）を入力する。現場用伝票に印字する。明細ごとの摘要は使わないため、特定の行についての指示もここに書く。

| キー | 動作 |
| --- | --- |
| Enter | 登録ボタンへ進む |
| Ctrl + Enter | 改行を入れる |
| Shift + Enter | 前の欄（スタンプの番号）へ戻る |
| ↑ / ↓ | 文の中で上下の行があれば行の移動、先頭の行の ↑・最後の行の ↓ は前・次の欄へ移る |

テンキーの流れを止めないよう Enter は次へ進むことに使い、改行は Ctrl + Enter に割り当てる。帯の高さに合わせて欄は 3 行分とし、それより長い文は欄の中でスクロールする。

**登録**

② の「登録して現場用伝票を印刷」で、① ② の入力をまとめて登録する（DB の関数 `create_order` で 1 つの transaction。table-design.md「受注の登録（create_order）」）。登録の前に ① ② の入力を確認し、エラーがあればその画面に戻ってエラーの欄にカーソルを置く。

### 受注入力で扱わないもの

次の項目は受注登録の画面では入力しない。

| 項目 | 扱い |
| --- | --- |
| 仕入単価・仕入金額（材料の行・加工の行） | 自動計算して保存するが、画面には出さない。別途見積もりの単価の入力、自動で入った単価の確認・修正は、送り状の発行後に行う「仕入入力」の画面で行う（basic-design.md「仕入入力」） |
| 加工の単位（個 / kg） | 単価だけに関係するため、仕入入力で扱う。受注登録では初期値の「個」で保存する |
| 梱包数（`order_items.package_count`） | 受注後のラベル発行メニューで入力する |
| 実重量（`order_items.actual_weight`） | 手入力が必要な行（アイトレなど）は、送り状発行の画面で必要な行だけ入力する。寸法切・ベタ丸・ドーナツのように寸法から求まるものは自動計算する |
| 売上単価（`order_items.sales_unit_price`） | MVP の対象外。営業が決めるものであり、将来の営業システム連携（Phase2）で扱う。列は残すが MVP では使用しない |
| フリー区分（重量の手入力） | MVP では作らない。必要になれば区分に追加する |

### 入力時の挙動

| 操作 | システムの動作 |
| --- | --- |
| 受注登録待ちの一覧で加工区分を選ぶ（受付の機能ができてから） | ① を開き、受付の値を初期値として入れる（処理区分は 0 新規） |
| ① を開く | 処理区分にカーソルを置く |
| 処理区分で 1 変更・2 削除を選択 | 受注 No. の入力欄を有効にし、入力された受注を呼び出す（ハイフンを入力できる） |
| 部材区分で 4 SPL を入力 | 継手番号・ショットの欄を表示し、明細をスプライス専用に切り替える。ショットが空欄なら 1 有を入れる |
| ショットで 1 有を選択 | ② の下の帯のスタンプに「ショット加工」を自動で追加する（変更不可） |
| 得意先を選択 | 当てはまる得意先の注意事項を ② に表示、指定スタンプにチェック |
| 配達で 9 フリーを選択 | 文字を入力する欄を表示する |
| 受注情報を確定して次へ | 売り先が空ならエラー。② に進み、明細の最初の行にカーソルを置く |
| F2 | 注文書のパネルを開閉する |
| 切断・区分で 71 定尺を入力 | 寸法欄を定尺サイズの入力に切り替える。製鋼法を「—」にする |
| 切断・区分を入力 | 寸法の入力欄を区分に応じて切り替える |
| 切断・区分で 9 を入力 | 加工の行に切り替え、同じ欄を加工方法の番号の欄にする |
| 種類を選択 | 材質・メーカーの選択肢を絞り込む。材質エキストラを適用しない種類なら製鋼法を「—」にする。普通板以外なら強調する |
| 材質を入力・変更 | 製鋼法をその材質の初期値にする。SS400 以外なら強調する |
| 製鋼法を材質の初期値と違う値にする | 製鋼法の欄を強調する |
| メーカーを指定 | メーカーの欄を強調する |
| 板厚を入力 | 取り扱いのない板厚なら行を強調表示してメッセージを出す |
| 縞板でメーカーまたは板厚を変更 | メーカーと板厚の組み合わせに単位質量が登録されているかを確認し、なければエラーを出す |
| 寸法・数量を入力 | 重量を計算する。仕入単価も裏で計算する（画面には出さない） |
| 加工方法を入力 | 加工の項目の入力欄を、加工種別の入力の形に切り替える。その加工種別を条件にした得意先の注意事項を表示する |
| 加工の行の穴径・母材の板厚を入力 | 当てはまる加工の注意事項を、その加工の行のすぐ下に表示する |
| 曲げのヶ所・曲げ方で 9 フリーを選択 | 数字（ヶ所数）・文字（曲げ方）を入力する欄を表示する |
| 材料の行の数量を変更 | ぶら下がる穴・曲げの加工の行の数量を計算し直す |
| 何も入力していない最後の行の切断・区分で Enter | 下の帯のスタンプの番号の欄へ移る |
| 番号の欄で上限の桁まで打つ | 存在する番号なら次の欄へ進む。存在しない番号ならその欄でエラーを出す |
| 切断・区分で「-」→ 行番号 → Enter | その番号の材料の行を加工の行ごと複写する |
| スタンプの番号を打って Enter | そのスタンプのチェックを付け外しする |
| フリーコメントで Ctrl + Enter | 改行を入れる |
| 登録 | 受注番号を採番し、現場用伝票を印刷する。受付の機能ができたら、そのあと「同じ受付から続けて登録」（① に戻る）か「この区分の起票を完了」（受注登録待ちから外す）を選ぶ |
| 処理区分 2 削除で確定 | 受注を論理削除する。送り状（出荷実績）がある受注はエラーを出して削除しない |

最低保証重量の判定（kg 単価か枚単価か）は入力者に選択させない。寸法と種類・材質から 1 枚あたりの重量を算出して自動判定する。

### 受注の削除・修正

処理区分 2 削除は論理削除とする。受注の行は消さずに削除済みの印（`orders.deleted_at`）を付け、受注一覧・現場用伝票・送り状発行などの対象から外す。誤って削除した場合の確認や、過去の受注番号の追跡ができるようにするためである。

送り状（出荷実績）がある受注は削除できない。処理区分 2 削除で呼び出した受注に出荷実績があれば、エラーを出して削除させない。DB 側でも同じ制限をかける（table-design.md `orders` の「論理削除」を参照）。

仕入入力を作るときに、この制限を「送り状がある受注は修正も削除もできない」に広げる。修正は「仕入を削除 → 送り状を削除 → 受注を修正」の逆順でしか行えないようにする（basic-design.md「仕入入力」）。
